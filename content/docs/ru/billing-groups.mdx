## 1. Два способа оплаты

| Способ | Как списываются средства | Когда подходит |
| - | - | - |
| Оплата по факту с баланса | Цена модели умножается на коэффициент группы, к которой относится API Key, и списывается с баланса аккаунта | Повседневные вызовы, работа с несколькими моделями, разовые тесты |

## 3. Как считается коэффициент

Коэффициент — это множитель к базовой цене модели. Чем он ниже, тем меньше спишется за один и тот же запрос к той же модели:

```text
Фактический расход ≈ Базовый расход модели × Коэффициент группы
```

<RatioExampleTable base={10} groups={['codex-team', 'codex-plus', 'claude', 'claudemax']} />

Базовый расход модели здесь — не фиксированная величина: он меняется в зависимости от длины входа и выхода, попаданий в кэш и цены самой модели. Часть, попавшая в кэш, обычно дешевле.

<Callout type="warn" title="Не смотрите только на коэффициент">
  Коэффициент — не единственная составляющая цены. У разных моделей сильно различаются базовая цена, выходной коэффициент и коэффициент кэша; модели для изображений и видео могут стоить фиксированно. Оценивая расходы, ориентируйтесь на текущие цены на странице цен или в списке моделей консоли.
</Callout>

## 4. Выбирайте правильную группу при создании API Key

Создавая API Key в разделе **Консоль → API Keys** (API 密钥), помните: группа ключа определяет диапазон доступных моделей, коэффициент списания и upstream-пул ресурсов. Выбрать её нужно правильно.

![Выбор группы при создании API Key](/img/start/api-v2-06-token-create.png)

При создании API Key обращайте внимание на:

- **Группа**: определяет, какие модели может вызывать этот ключ и по какому коэффициенту списываются средства.
- **Квота**: ограничивает, сколько лимитов может потратить этот ключ; безлимитная квота не означает отсутствие списаний — действуют ограничения баланса аккаунта.
- **Список разрешённых моделей**: без необходимости ограничивать не стоит — только если вы явно хотите разрешить несколько конкретных моделей.
- **Белый список IP**: подходит для серверов с фиксированным исходящим IP; для локальной разработки используйте осторожно, чтобы после смены IP вызовы не сломались.

Типичные признаки неправильно выбранной группы:

- Модели видны в списке моделей, но при вызове текущим ключом появляется `model not found`, `model not available` или ошибка прав доступа.
- Модель вызывается, но коэффициент списания или стабильность не те, на которые вы рассчитывали.

## 6. Сверяйте фактический расход после использования

После вызовов ориентируйтесь на записи в **Консоль → Журналы использования**, чтобы сверить фактический расход. В командной работе используйте строки детализации по группам и пользователям/ключам в журналах, чтобы понять, проблема в конкретном ключе, конкретном участнике или во всей группе.

| Вопрос | Какие поля смотреть |
| - | - |
| Какая группа расходует больше всего | Группа, расход, число запросов |
| Аномалия только у одного участника | Детальные строки «Пользователь / API Key» |
| Срабатывает ли кэш | Доля попаданий в кэш, кэшированные токены, доля кэшированных запросов |
| Это проблема пула ресурсов | Успешность группы, число ошибок, причины сбоев |
| Высокая стоимость из-за длинного контекста или большого вывода | Расход на один успешный вызов, среднее время, кэшированные токены |

## 7. Замечания по использованию

1. Разные группы соответствуют разным пулам ресурсов — выбирайте под свой сценарий.
2. В длинных диалогах Claude разумно используйте кэширование контекста; фактические попадания в кэш зависят от настроек клиента, модели и интервалов между запросами.
3. Коэффициенты групп, доступность моделей и состояние ресурсов определяются актуальными данными на сайте.

## 8. Диагностика аномалий расхода и прав доступа

При аномальном расходе или недоступности модели диагностируйте в таком порядке:

1. Убедитесь, что группа, к которой привязан текущий ключ, включает нужную модель.
2. Проверьте, что баланс аккаунта достаточен.
3. Откройте **Консоль → Журналы использования** и отфильтруйте по времени, модели, ключу, группе и ID запроса.
4. Отфильтруйте журнал по столбцу группы, чтобы понять: проблема в конкретном API Key или в пуле ресурсов группы.
5. Если определить причину не удаётся, обратитесь в поддержку и укажите номер заказа, имя ключа, группу, название модели, время запроса и ID запроса.
