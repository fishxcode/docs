## 1. Сначала различайте три способа оплаты

Стоимость в FishXCode не определяется одним правилом. Прежде всего выясните, каким способом вы пользуетесь:

| Способ | На что смотреть | Когда подходит |
| - | - | - |
| Оплата по факту | Базовая цена модели, коэффициенты ввода, вывода и кэша, группа токена | Вызовы API с баланса, разовые тесты, работа с несколькими моделями |
| Подписка | Срок действия, общая квота, дневной и месячный лимиты, применимая группа | Фиксированный бюджет команды, долгосрочная работа с Codex / Claude |
| Группа токена | Какие модели может вызывать ключ, через какой пул ресурсов идут запросы, по какому коэффициенту списываются средства | Создание ключей, разделение проектов, учёт затрат по команде |

Правила тарифов удобно читать вместе с [обзором тарифных планов](/ru/subscription-plans): эта страница объясняет, «как модели, коэффициенты и группы влияют на списание», а страница тарифов — «как после покупки действуют квота, срок, число запросов и лимиты».

## 2. Страница цен: начните с карточек тарифов

По карточкам тарифов на странице цен удобно быстро оценить, сколько квоты или запросов даёт тариф, как долго он действует, сколько можно использовать в день и есть ли особые правила пересчёта.

![Пример списка подписок](/img/plans/subscription-plans.png)

В карточке тарифа обратите внимание на следующие поля:

| Поле | Значение | Как читать |
| - | - | - |
| Текущая цена | Цена покупки и срок действия | Например, `¥320.00 / 1 месяц` — цена за один месяц |
| Стоимость одного запроса | Ориентировочная стоимость: цена тарифа, делённая на общее число запросов | Помогает сравнить выгодность похожих тарифов с поштучной оплатой |
| Лимит тарифа | Общая квота или общее число запросов по тарифу | Например, `15000 запросов` — по тарифу можно сделать в сумме не более 15000 базовых запросов |
| Дневной лимит | Максимум квоты или запросов в сутки | Например, `500 запросов/день`; после его достижения обычно нужно дождаться сброса |
| Время сброса | Когда восстанавливается лимит за период | Например, `сброс ежедневно в 08:00:00` |
| Область действия | Группа, модели и поставщики, к которым привязан тариф | Например, `sub_plan_claude_mini_plus · 9 моделей · 2 поставщика` |
| Правила поштучной оплаты | Пересчитывается ли число запросов для особых моделей с учётом коэффициента | Например, Claude Opus 4.8 и GPT-5.5 считаются как `2.5 * 1 запрос` |

<Callout type="idea" title="Пример: списание по тарифу с поштучной оплатой">
  В описании тарифа указано `500 запросов/день, 15000 запросов в месяц` и пояснение `Claude Opus 4.8, GPT-5.5 считаются как 2.5 * 1 запрос`.

  Один успешный запрос к обычной модели, как правило, засчитывается как 1 запрос, а один успешный запрос к Claude Opus 4.8 или GPT-5.5 — как 2,5 запроса. Иными словами, если весь день пользоваться только такими моделями с повышенным коэффициентом, дневной лимит `500 запросов/день` может быть исчерпан примерно за 200 успешных запросов.
</Callout>

## 3. Условия тарифа: лимиты, сброс и доступные модели

На странице условий или подробностей тарифа доступны более детальные поля. Этот раздел помогает понять, «что именно вы сможете использовать после покупки».

![Пример условий тарифа с поштучной оплатой](/img/plans/by-number-of-times.png)

На скриншоте видно:

- **Дневной лимит**: максимальное число запросов в сутки.
- **Лимит тарифа**: общее число запросов за весь срок действия.
- **Время сброса**: когда восстанавливается дневной лимит.
- **Период продаж**: некоторые тарифы можно купить только в определённые периоды.
- **Поставщики**: upstream-провайдеры, которые охватывает тариф.
- **Доступные модели**: список моделей, которые после покупки можно вызывать в группе тарифа.
- **Группа апгрейда**: группа, в которую вы автоматически попадаете или к которой привязываетесь после покупки, например `sub_plan_claude_mini_max`.

<Callout type="warn" title="Смотрите тариф и группу вместе">
  Страница тарифа сообщает «квоту и лимиты», а группа — «модели и каналы». Если тариф поддерживает некую группу апгрейда, но ваш ключ фактически не привязан к этому тарифу или группе, запросы всё равно могут оплачиваться с баланса или завершаться ошибкой доступа.
</Callout>

## 4. Покупка: перед оплатой проверьте срок действия и способ активации

После нажатия кнопки покупки откроется окно оформления. Здесь вы в последний раз проверяете, какой тариф покупаете, сколько он стоит, как долго действует и активируется ли он автоматически.

![Пример покупки подписки](/img/plans/buyplan.png)

Перед покупкой проверьте:

| Поле | Почему это важно |
| - | - |
| Текущая цена | Показывает сумму к оплате и помогает не ошибиться с тарифом |
| Срок действия | По его истечении условия тарифа перестают действовать |
| Квота токенов / число запросов | Определяет общий объём, доступный по тарифу |
| Тип тарифа | Автоматическая активация, ручная выдача или другой способ выдачи влияют на то, когда тариф начнёт действовать |
| Способ оплаты | Проверьте, через Alipay, WeChat или другой способ вы платите |
| Условия покупки | Правила возврата, активации, ограничения на покупку и послепродажное обслуживание — согласно информации на странице |

Если вы хотите лишь ненадолго протестировать модель, покупать тариф сначала не обязательно — можно вызывать её с оплатой по факту с баланса.

## 5. Оплата по факту: вызов моделей напрямую с баланса

Оплата по факту означает, что вы не покупаете фиксированный тариф, а вызываете модели напрямую за счёт баланса аккаунта. Это удобно, чтобы сначала наладить работу инструмента, при редких вызовах, при работе с несколькими моделями или когда вы ещё не решили, какой тариф купить.

Базовый порядок действий при оплате по факту:

1. На [странице цен](https://fishxcode.com/pricing?currency=CNY) проверьте, в каких группах доступна нужная модель.
2. В разделе **Консоль → Управление токенами** создайте обычный токен и выберите подходящую группу токена.
3. Укажите ключ в Claude Code, Codex, Cursor, RooCode или в собственной программе.
4. После каждого успешного запроса система списывает средства с баланса с учётом цены модели, входных и выходных токенов, попаданий в кэш и коэффициента группы.
5. Сверьте фактический расход в разделе **Консоль → Журнал использования**.

Списание при оплате по факту можно представить так:

```text
Фактический расход ≈ базовый расход модели × коэффициент группы + поправки на вывод, кэш и т. п.
```

«Базовый расход модели» здесь не фиксирован: он меняется в зависимости от длины ввода и вывода, попаданий в кэш и цены самой модели. Модели с фиксированной ценой, например для изображений и видео, не стоит оценивать по обычным текстовым токенам.

Чем оплата по факту с баланса отличается от тарифов:

| Тип | Особенности | Когда подходит |
| - | - | - |
| Оплата по факту с баланса | Списывается столько, сколько использовано; при нехватке баланса вызовы прекращаются | Разовые тесты, работа с несколькими моделями, редкое использование |
| Тарифы Codex | Обычно ограничены сроком действия и квотой | Задачи программирования с Codex / GPT, фиксированный бюджет команды |
| Тарифы с поштучной оплатой | Учитывается число успешных запросов; возможен дневной лимит | Когда нужно контролировать бюджет по числу запросов |
| Тарифы ClaudeMax | Ориентированы на привилегии аккаунта и работу через Claude Code | Подписка на официальные аккаунты Claude Code |

<Callout type="idea" title="Пример: когда лучше платить по факту">
  Если вы просто хотите проверить, подключается ли инструмент к FishXCode, создайте обычный токен в группе `default` или в группе, рекомендованной для нужной модели, и отправьте несколько запросов. Убедившись, что модель, группа и настройки клиента верны, решайте по объёму использования, стоит ли покупать тариф Codex, тариф с поштучной оплатой или тариф ClaudeMax.
</Callout>

<Callout type="warn" title="Оплата по факту тоже зависит от группы">
  Наличие баланса не означает, что любой ключ может вызывать любую модель. Доступность модели по-прежнему определяется группой токена. При ошибках `model not found`, `model not available` или ошибках доступа сначала проверьте, входит ли нужная модель в группу ключа.
</Callout>

## 6. Токены: группа определяет, какие модели доступны ключу

Группу токена можно понимать как **набор моделей, доступных этому API Key, + правила коэффициентов списания + пул ресурсов upstream-провайдера**. При создании ключа обязательно выберите правильную группу.

![Выбор группы при создании токена](/img/start/api-06-token-create.png)

При создании обычного токена обратите внимание на следующее:

- **Группа токена**: определяет, какие модели может вызывать ключ.
- **Настройка квоты**: ограничивает, сколько квоты может израсходовать ключ; безлимитная квота не означает, что средства не списываются, — по-прежнему действуют ограничения баланса аккаунта или тарифа.
- **Список разрешённых моделей**: без необходимости не ограничивайте модели, если только вы точно не хотите разрешить лишь некоторые из них.
- **Белый список IP**: подходит для серверов с фиксированным внешним IP; при локальной разработке используйте его осторожно, иначе после смены IP вызовы перестанут проходить.

Типичные признаки неверно выбранной группы:

- Модель видна в списке моделей, но при вызове с текущим ключом возникает `model not found`, `model not available` или ошибка доступа.
- Модель вызывается, но коэффициент списания, работа кэша или стабильность не соответствуют ожидаемому уровню.
- Ключи тарифа и обычные ключи с оплатой с баланса используются вперемешку, из-за чего квота расходуется не из того источника или статистику трудно интерпретировать.

## 7. Токены тарифа: командные ключи на основе тарифа

После покупки тарифа система может автоматически создать токен доступа к тарифу; кроме того, на основе тарифа можно создавать новые командные токены. Это удобно, когда несколько человек делят квоту тарифа, но расход нужно разделять по участникам или проектам.

![Пример создания токена на основе тарифа](/img/plans/create.png)

При создании токена на основе тарифа обратите внимание на следующие поля:

| Поле | Описание |
| - | - |
| Создать на основе тарифа | Выберите тариф для привязки; после привязки срок действия, группа и ограничения по моделям наследуются от тарифа |
| Название | Называйте токен по участнику, проекту или сервису — так удобнее фильтровать журналы |
| Группа токена | По умолчанию совпадает с группой тарифа или пользователя; не переключайте её без причины на неподходящую группу |
| Срок действия | Обычно не должен превышать срок действия тарифа |
| Квота токена тарифа | Ограничивает, сколько квоты тарифа может израсходовать этот дочерний ключ |

<Callout type="idea" title="Пример: как разделить ключи в команде">
  Если одним тарифом Codex пользуются 5 участников, не стоит давать всем один и тот же ключ. Создайте для каждого участника отдельный токен, например `codex-zhangsan`, `codex-lisi`. Тогда в журнале использования или в состоянии групп сразу будет видно, кто расходует больше, у кого больше ошибок и какому проекту нужен лимит.
</Callout>

| `grok` | 【Выделенная линия｜Grok】Группа моделей серии Grok; подходит для диалогов, рассуждений и визуальных задач с xAI Grok. | Диалоги, рассуждения и визуальные задачи с Grok |

<Callout type="info" title="Группы могут меняться">
  Платформа может добавлять, отключать или изменять группы. Документация объясняет логику выбора группы, но не заменяет актуальные цены и права доступа, которые отображаются в консоли.
</Callout>

## 9. Примеры коэффициентов и списаний

Коэффициент — это просто множитель к базовой цене модели. Чем ниже коэффициент, тем обычно меньше списание за один и тот же запрос к одной и той же модели.

| Базовый расход модели | Коэффициент группы или модели | Расчётное списание |
| - | - | - |
| 10 единиц квоты | `1x` | 10 единиц квоты |
| 10 единиц квоты | `0.5x` | 5 единиц квоты |
| 10 единиц квоты | `0.1x` | 1 единица квоты |
| 10 единиц квоты | `2.5x` | 25 единиц квоты |

Примеры, приближенные к реальным вызовам:

| Сценарий | Как оценить |
| - | - |
| Базовый расход модели — 8 единиц квоты, коэффициент `1x` | Спишется около 8 единиц квоты |
| Тот же запрос с коэффициентом `0.5x` | Спишется около 4 единиц квоты |
| Тот же запрос с коэффициентом модели `2.5x` | Спишется около 20 единиц квоты |
| Запрос с длинным контекстом и попаданием в кэш | Кэшированная часть обычно дешевле; окончательная сумма — по записи в журнале |

<Callout type="warn" title="Смотрите не только на коэффициент">
  Коэффициент — не единственный показатель цены. Базовые цены, коэффициенты вывода и кэша у разных моделей сильно различаются, а у моделей для изображений и видео цена может быть фиксированной. Для оценки затрат ориентируйтесь на текущие цены на странице цен или в списке моделей в консоли.
</Callout>

## 10. Как сверить фактический расход после использования

После вызовов не оценивайте затраты только по расчёту — проверьте фактический расход в разделе **Консоль → Журнал использования**. В командных сценариях и при работе по тарифу дополнительно используйте **Состояние групп**, чтобы понять, связана ли проблема с одним ключом, одним пользователем или всей группой.

![Пример состояния групп](/img/plans/statistics.png)

Состояние групп помогает ответить на такие вопросы:

| Вопрос | Какие поля смотреть |
| - | - |
| Какая группа расходует больше всего | Группа, расход, число запросов |
| Сбоит ли только один участник | Строки детализации по пользователям / токенам |
| Работает ли кэш | Доля попаданий в кэш, кэш-токены, доля запросов с кэшем |
| Не в пуле ли ресурсов проблема | Успешность группы, число ошибок, причины сбоев |
| Не длинный ли контекст или большой вывод повышают затраты | Расход на успешный запрос, среднее время, кэш-токены |

<Callout type="idea" title="Пример: разбор в команде">
  Если общая успешность группы `codex_sub` в норме, но расход на успешный запрос у токена одного из участников заметно выше, чем у остальных, сначала проверьте, не запускает ли этот участник задачи с длинным контекстом, большим выводом или повторяющиеся задачи. Если же падает успешность всей группы, ищите причину в пуле ресурсов группы, состоянии upstream-провайдера или правах тарифа.
</Callout>

## 11. Как быстро выбрать группу

| Сценарий | С чего начать | Почему |

| Не знаете, что выбрать | `default` или группа, рекомендованная в консоли | Сначала убедитесь, что инструмент настроен правильно |

## 12. Диагностика аномального расхода или проблем с доступом

При аномальном расходе или недоступности модели рекомендуем проверять в таком порядке:

1. Убедитесь, что группа токена, к которой привязан текущий ключ, включает нужную модель.
2. Проверьте, достаточно ли баланса, не истёк ли срок действия тарифа, не исчерпаны ли дневной или месячный лимит либо общая квота.
3. Откройте **Консоль → Журнал использования** и отфильтруйте записи по времени, модели, токену, группе и ID запроса.
4. Сравните с данными на странице [Состояние групп](/ru/group-health), чтобы понять, связана ли проблема с одним токеном или с пулом ресурсов группы.
5. Если причину по-прежнему не удаётся определить, обратитесь в поддержку и укажите номер заказа, название токена, группу, название модели, время запроса и ID запроса.
