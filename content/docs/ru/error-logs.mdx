Журнал ошибок помогает выяснить конкретную причину сбоя отдельного запроса. При диагностике сначала посмотрите [Состояние групп](/ru/group-health), чтобы оценить масштаб проблемы, а затем найдите нужный запрос по `request_id` из журнала ошибок.

Где найти: [Консоль → Журнал использования](https://fishxcode.com/console/log). Переключите тип журнала на **Журнал ошибок** — после этого записи можно фильтровать по времени, модели, токену, группе, ID запроса, сообщению об ошибке и коду состояния.

<Callout type="idea" title="Быстрая проверка">
  - `request_id` — чтобы найти конкретный запрос
  - `status_code` — чтобы сгруппировать ошибки по типу
  - `content` — чтобы искать по ключевым словам ошибки
  - `group` — чтобы понять, сосредоточена ли проблема в одной группе
</Callout>

## Описание полей

| Поле | Значение | Чем полезно при диагностике |
| - | - | - |
| Время | Когда произошёл сбой запроса | Показывает, продолжается ли проблема |
| Модель | Название модели, использованной в запросе | Показывает, затронута ли только одна модель |
| Токен | API Key или название токена, использованного в запросе | Показывает, затронут ли только один токен |
| Группа | Группа тарифа, модели или ресурсов upstream-провайдера, к которой относится запрос | Показывает, сосредоточен ли сбой в одной группе |
| ID запроса | Уникальный идентификатор запроса, обычно `request_id` | Его в первую очередь нужно сообщить в поддержку |
| Сообщение об ошибке | Текст причины сбоя, обычно содержит `content` | Позволяет найти конкретную ошибку по ключевым словам |
| Код состояния | Код состояния HTTP или upstream-провайдера, например `401`, `429`, `502` | Помогает быстро классифицировать ошибку |

## Порядок диагностики

1. Скопируйте `request_id` из ответа API или журнала и сначала найдите именно этот запрос.
2. Если `request_id` нет, сузьте поиск по периоду, модели и токену.
3. Сгруппируйте ошибки по коду состояния, например `401`, `413`, `429`, `502`, `503`.
4. Ищите по ключевым словам в сообщении об ошибке, например `Invalid API key`, `daily limit exceeded`, `Upstream request failed`.
5. Если одинаковые ошибки массово возникают в одной группе, откройте [Состояние групп](/ru/group-health) и оцените масштаб проблемы.

## Определение причины

Журнал ошибок помогает предварительно определить, к чему относится проблема: к «проблемам использования», «проблемам upstream-провайдера» или «проблемам платформы». Одного кода состояния для этого мало — нужно учитывать и масштаб:

| Причина | Критерий | Типичные проявления | Что делать в первую очередь |
| - | - | - | - |
| Проблема использования | Затрагивает только один запрос, один токен или конкретную настройку клиента | Неверный формат тела запроса, несовпадение параметров, ошибка при копировании токена, слишком большой контекст, неверный путь эндпоинта | Проверьте локальные настройки, тело запроса, название модели, токен и версию инструмента |
| Проблема upstream-провайдера | Во многих запросах сразу возникают сбои upstream-провайдера, тайм-ауты шлюза или ограничения квоты upstream-провайдера | `Upstream request failed`, `all upstreams failed`, `bad response status code 502/524`, ограничение частоты для аккаунтов upstream-провайдера | Повторите позже, снизьте параллелизм, при необходимости смените модель или группу |
| Проблема платформы | Недоступны узлы платформы, пулы ресурсов или каналы | `system disk overloaded`, `No available accounts`, `No available channel`, `Service Unavailable` на стороне платформы | Повторите позже; если ошибка сохраняется, обратитесь в поддержку и укажите группу, период и `request_id` |
| Нужно смотреть на группу | По одной записи журнала нельзя точно определить, на чьей стороне проблема | Ошибки вроде `429`, `502`, `503`, у которых может быть несколько причин | Откройте [Состояние групп](/ru/group-health) и проверьте, носит ли сбой массовый характер |

<Callout type="warn" title="Важно">
  Не определяйте, на чьей стороне проблема, по одной ошибке `502` или `503`. Сбой отдельного запроса может быть случайной нестабильностью upstream-провайдера; только массовые сбои в одной группе за один и тот же период — повод считать проблему связанной с ресурсами upstream-провайдера или платформы.
</Callout>

## Классификация кодов состояния

| Код состояния | Типичное значение | Предварительная причина | Что делать в первую очередь |
| - | - | - | - |
| `400` | Формат тела запроса, параметры или сообщения инструментов не соответствуют требованиям | Проблема использования | Проверьте тело запроса клиента, путь эндпоинта и schema инструментов |
| `401` | Токен недействителен, не активирован или не прошёл аутентификацию | Проблема использования | Заново скопируйте токен и проверьте его статус |
| `403` | Upstream-провайдер отказал в доступе, обычно из-за прав или ограничений доступа к модели | Проблема использования или upstream-провайдера | Проверьте тариф, группу и права на модель |
| `413` | Слишком большое тело запроса | Проблема использования | Сократите контекст, разделите файлы, сожмите изображения |
| `429` | Ограничение частоты, дневной квоты или охлаждение учётных данных | Нужно смотреть на группу | Снизьте параллелизм, дождитесь восстановления квоты или окончания охлаждения |
| `500` | Внутренняя ошибка шлюза или обёрнутая шлюзом ошибка upstream-провайдера | Нужно смотреть на сообщение об ошибке | Определите настоящую причину по сообщению об ошибке |
| `502` | Сбой сервиса upstream-провайдера или промежуточной сети | Проблема upstream-провайдера или сетевого маршрута | Повторите позже, при необходимости смените модель или группу |
| `503` | Сервис, канал, аккаунт или ресурсы платформы временно недоступны | Проблема upstream-провайдера или платформы | Повторите позже; если ошибка сохраняется, обратитесь в поддержку |
| `504` / `521` / `522` / `524` | Тайм-аут подключения, чтения или ответа шлюза | Проблема upstream-провайдера или сетевого маршрута | Сократите длительные задачи и повторите позже |

## Частые сообщения об ошибках

| Текст в журнале ошибок | Значение | Предварительная причина | Что делать |
| - | - | - | - |
| `status_code=401, Invalid token` | Токен недействителен, скопирован с ошибкой или истёк | Проблема использования | Заново скопируйте токен из консоли и убедитесь, что в нём нет лишних пробелов |
| `status_code=401, Invalid API key or key is pending admin approval` | API Key недействителен, или новый ключ ещё ожидает проверки или активации | Проблема использования или статус аккаунта | Убедитесь, что используете актуальный токен из консоли; если вы только что создали ключ или сменили тариф, дождитесь, пока изменения вступят в силу, и повторите попытку; если ошибка остаётся, обратитесь в поддержку |
| `status_code=403, bad response status code 403` | Upstream-провайдер отклонил запрос, обычно из-за прав доступа, статуса аккаунта или ограничений доступа к модели | Проблема использования или upstream-провайдера | Проверьте токен, группу тарифа и права на модель; если ошибка повторяется, смените модель или обратитесь в поддержку, указав `request_id` |
| `status_code=413, openai_error` / `bad response status code 413` | Слишком большое тело запроса, обычно из-за объёмного контекста, файлов, изображений или результатов инструментов | Проблема использования | Сократите контекст, загружайте меньше данных за один раз, разделите большие файлы или сожмите изображения и повторите попытку |
| `status_code=429, Account RPM limit exceeded` | Аккаунт upstream-провайдера превысил лимит запросов в минуту | Проблема использования или ограничение upstream-провайдера | Снизьте параллелизм и частоту повторов, попробуйте позже |
| `status_code=429, Account daily limit exceeded` | Аккаунт upstream-провайдера достиг дневного лимита запросов | Ограничение upstream-провайдера | Дождитесь сброса дневной квоты или переключитесь на другую доступную модель или группу |
| `status_code=429, All credentials for model ... are cooling down` | Все учётные данные upstream-провайдера для текущей модели находятся в периоде охлаждения | Ограничение upstream-провайдера | Реже повторяйте запросы и дождитесь окончания охлаждения; для срочных задач временно смените модель |
| `status_code=500, 请求失败 [429]: {"message":"Too many requests, please wait before trying again."}` | Upstream-провайдер вернул ограничение частоты в виде `429`, но шлюз обернул его в `500` | Проблема использования или ограничение upstream-провайдера | Действуйте как при ограничении частоты: снизьте параллелизм, увеличьте интервал между повторами и не повторяйте запросы сразу подряд |
| `status_code=500, auth_unavailable: no auth available` | Для текущей модели или группы временно нет доступных ресурсов аутентификации upstream-провайдера | Проблема платформы | Повторите позже; если ошибка сохраняется, переключитесь на доступную модель или группу либо обратитесь в поддержку, чтобы проверить состояние тарифа и группы |
| `status_code=502, Upstream request failed` / `bad response status code 502` / `all upstreams failed` | Сервис upstream-провайдера или промежуточная сеть вернули ошибку, либо запросы ко всем доступным upstream-провайдерам завершились сбоем | Проблема upstream-провайдера | Повторите позже; если ошибка сохраняется, смените модель или обратитесь в поддержку, указав `request_id` |
| `status_code=502, openai_error` | OpenAI-совместимый upstream-провайдер вернул ошибку, но шлюз не получил более точной причины | Проблема upstream-провайдера | Сначала действуйте как при сбое upstream-провайдера; если один и тот же запрос стабильно воспроизводит ошибку, сократите контекст и передайте `request_id` в поддержку |
| `status_code=502, The origin web server returned an invalid or incomplete response to Cloudflare` | Исходный сервер upstream-провайдера вернул через Cloudflare некорректный ответ | Проблема upstream-провайдера | Обычно это временный сбой upstream-провайдера; повторите позже |
| `status_code=500, upstream error: do request failed` | Не удалось отправить запрос upstream-провайдеру, обычно из-за проблем с сетевым подключением или временной недоступности провайдера | Проблема upstream-провайдера или сетевого маршрута | Повторите позже; если ошибка сохраняется, передайте `request_id` в поддержку для диагностики |
| `status_code=520, bad response status code 520` | Cloudflare вернул неизвестную ошибку; обычно это значит, что upstream-провайдер ответил некорректно или соединение было прервано | Проблема upstream-провайдера или сетевого маршрута | Повторите позже; при массовых ошибках действуйте как при сбое upstream-провайдера |
| `status_code=521` / `522` / `504` / `524` | Тайм-аут подключения, чтения или ответа Cloudflare либо шлюза upstream-провайдера | Проблема upstream-провайдера или сетевого маршрута | Сначала повторите позже; если ошибка возникает только в длительных задачах, сократите контекст, длину вывода или цепочку вызовов инструментов |
| `status_code=503, Service Unavailable` | Сервис upstream-провайдера временно недоступен или в текущей группе нет доступных ресурсов | Нужно смотреть на группу | Повторите позже; если ошибка сохраняется, смените модель или группу либо обратитесь в поддержку, чтобы проверить состояние ресурсов |
| `status_code=503, system disk overloaded` | Диск узла сервиса переполнен, и платформа временно отклоняет запросы, чтобы защитить сервис | Проблема платформы | Это проблема ёмкости или состояния узла на стороне платформы; повторите позже, а если ошибка сохраняется, обратитесь в поддержку |
| `status_code=503, No available accounts: no available accounts` | В текущей группе нет доступных аккаунтов upstream-провайдера | Проблема платформы | Смените модель или группу либо повторите позже; если ошибка держится долго, обратитесь в поддержку, чтобы проверить пул ресурсов |
| `status_code=503, No available channel for model ... under group ...` | В текущей группе нет доступного канала для этой модели | Проблема использования или платформы | Проверьте название модели и состав тарифа, переключитесь на модель, которую поддерживает эта группа |
| `status_code=503, model gpt-image-2 is only supported on /v1/images/generations and /v1/images/edits` | Модель для изображений вызвана через неподходящий эндпоинт | Проблема использования | Отправляйте запросы на генерацию и редактирование изображений на соответствующие эндпоинты images |
| `status_code=500, Image source is a local path that is not readable from this server` | В запросе есть локальный путь к изображению, который upstream-провайдер сейчас не может прочитать; из-за этого терминал может перестать реагировать на ввод | Проблема использования | Во frontend-проектах сначала проверьте файлы блокировки зависимостей (`lock`): удалите соответствующие lock-файлы или уберите из них ошибочные поля `png`, а затем заново откройте сессию; если нужно и дальше передавать изображения, используйте публичный URL изображения `http(s)` или передавайте `data:image/...` base64 |
| `status_code=500, failed to parse multipart form` | Формат тела запроса на загрузку изображения или файла не соответствует требованиям API | Проблема использования | Проверьте имена полей `multipart/form-data`, поле файла и заголовки запроса; не задавайте boundary вручную с ошибками |
| `status_code=400, Invalid request: prompt is required` / `解析 Images 请求失败: prompt 不能为空` | В запросе на генерацию или редактирование изображения нет `prompt` | Проблема использования | Передайте непустой `prompt` и убедитесь, что запрос отправляется на эндпоинт изображений |
| `status_code=400, Unsupported parameter: messages` | Эндпоинт и формат параметров не совпадают; обычно так бывает, когда параметры Chat/Responses отправляются на эндпоинт, который не поддерживает `messages` | Проблема использования | Проверьте `base_url` инструмента, путь эндпоинта и тип модели; приведите тело запроса в соответствие с документацией целевого API |
| `tool_use ids were found without tool_result blocks immediately after` | Последовательность сообщений с вызовами инструментов не соответствует требованиям протокола Claude | Проблема использования | Следите, чтобы сразу после каждого `tool_use` шёл соответствующий `tool_result`; если сообщения формирует сам инструмент, обновите клиент или начните новую сессию |
| `Invalid schema for function ... None is not of type 'array'` | Schema функции инструмента не соответствует требованиям модели; обычно `parameters` или поле-массив пустое либо имеет неверный тип | Проблема использования | Проверьте определения MCP и инструментов: для полей-массивов передавайте `[]`, а schema параметров функции должна соответствовать JSON Schema |
| `status_code=500, not implemented` | Текущий эндпоинт, возможность модели или способ вызова инструментов пока не реализованы | Проблема использования или платформы | Убедитесь, что используете поддерживаемые эндпоинт и модель; при необходимости смените модель или уточните совместимость в поддержке |

## Действия по типу ошибки

### Аутентификация и права доступа

Обращайте внимание на `401`, `403`, `Invalid API key`, `pending admin approval`, `No available channel`. Сначала проверьте, что токен взят из консоли, скопирован полностью и имеет права на текущую модель и группу.

### Формат запроса

Обращайте внимание на `400`, `413`, `Unsupported parameter`, `prompt is required`, `Invalid schema`. Сначала проверьте путь эндпоинта, поля тела запроса, schema инструментов, параметры запроса изображений и размер контекста.

### Ограничения частоты и квоты

Обращайте внимание на `429`, `Max 10/min`, `daily limit exceeded`, `cooling down`. Не повторяйте запросы без паузы: снизьте параллелизм в соответствии с ограничением из журнала или дождитесь восстановления квоты или учётных данных.

### Ресурсы upstream-провайдеров и платформы

Обращайте внимание на `502`, `503`, `504`, `520`, `521`, `522`, `524`, `Service Unavailable`, `system disk overloaded`. Сначала повторите попытку позже; если ошибки массово возникают в одной группе, откройте [Состояние групп](/ru/group-health).

## Что сообщить в поддержку

С простыми проблемами сначала попробуйте разобраться самостоятельно с помощью страниц [Журнал ошибок](/ru/error-logs) и [Состояние групп](/ru/group-health). Если это не помогло, откройте подробности ошибки в журнале ошибок в `console/log` и нажмите значок копирования — данные для диагностики скопируются одним кликом. При обращении в поддержку сразу передайте техническим специалистам следующие сведения, чтобы не тратить время на уточнения:

- ID пользователя
- Период: когда проблема началась и когда проявилась в последний раз
- Название группы: `group`
- Название модели: модель, использованная в запросе
- Код состояния: например, `429`, `413`, `502`, `503`
- Текст ошибки: `error_reasons.content`
- ID запроса: `request_id` из записи журнала или ответа API
- Масштаб: один токен, одна модель, одна группа или сбой сразу в нескольких группах

<Callout type="idea" title="Итог">
  Журнал ошибок объясняет, «почему не удался именно этот запрос», а состояние групп показывает, «носит ли проблема массовый характер». Используйте их вместе — так диагностика будет самой эффективной.
</Callout>
