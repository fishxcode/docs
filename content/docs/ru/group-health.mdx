Состояние групп помогает понять, связан ли сбой вызова с отдельным запросом или это массовая проблема определённого тарифа, модели, группы upstream-провайдера или участника команды. Администраторы компаний и команд могут с его помощью быстро ответить на три вопроса:

- У какой группы за выбранный период снизилась успешность
- Какой пользователь или токен даёт основную часть запросов, расхода или ошибок
- Сосредоточены ли ошибки на одном токене или уже затрагивают всю группу

При диагностике сбоев API сначала посмотрите состояние групп, а затем откройте отдельную запись журнала использования, чтобы найти конкретный `request_id`.

<Callout type="info" title="Охват данных">
  Встроенная на этой странице публичная страница `status` показывает состояние групп, которыми за выбранный период пользуются все пользователи платформы FishXCode. Она отражает доступность групп в масштабе всей платформы — в реальном времени, беспристрастно и стабильно.

  Раздел **Журнал использования → Состояние групп** в консоли учитывает данные, доступные с правами текущего аккаунта. Обычные пользователи, как правило, видят только свои токены; администраторы компаний и команд могут просматривать использование командой в разрезе пользователей, имён пользователей, токенов и групп.
</Callout>

Вход в консоли: [Консоль → Журнал использования](https://fishxcode.com/usage-logs/common). В журнале ошибок или в статистике фильтруйте записи по периоду, модели, токену, группе, сообщению об ошибке и коду состояния.

## Поля списка

Столбцы списка в консоли и в CSV-экспорте совпадают. В списке есть строки двух типов:

- **Строки групп**: сводное состояние группы за выбранный период.
- **Строки токенов**: детализация по пользователям и токенам внутри группы; помогает администраторам компаний и команд находить нужного участника, проект или сервис.

| Поле | Тип строки | Описание | Как использовать |
| - | - | - | - |
| Тип | Строки групп и токенов | Показывает, является ли строка сводкой `Группа` или детализацией `Токен` | Сначала оцените общее состояние по строкам групп, затем найдите конкретного участника или токен по строкам токенов |
| Группа | Строки групп и токенов | Группы, встречавшиеся за выбранный период: группы с оплатой по факту, группы тарифов, группа по умолчанию или группы отдельных моделей | Помогает понять, сосредоточена ли проблема в определённом тарифе, модели или пуле ресурсов upstream-провайдера |
| ID пользователя | Строки токенов | ID пользователя, который использует токен | Помогает найти аккаунт участника при диагностике в компании |
| Имя пользователя | Строки токенов | Имя пользователя, который использует токен | Для командных отчётов, общения с участниками и проверки прав |
| Токен | Строки токенов | Название токена, заданное в консоли | Помогает понять, затрагивает ли проблема только один токен |
| Успешность | Строки групп и токенов | Успешность = успешные запросы / все запросы | Ниже 80% — повод присмотреться; если значение заметно ниже, чем в других строках той же группы, в первую очередь проверьте эту группу или токен |
| Запросы | Строки групп и токенов | Общее число запросов за выбранный период | При маленькой выборке не делайте поспешных выводов по успешности |
| Успешно | Строки групп и токенов | Число успешных запросов с ответом 2xx | Оценивайте доступность вместе с полями «Запросы» и «Ошибки» |
| Ошибки | Строки групп и токенов | Число запросов, завершившихся ошибкой (4xx/5xx) | При росте ошибок в первую очередь смотрите «Причины сбоев» и журнал ошибок |
| Расход | Строки групп и токенов | Суммарный расход квоты за выбранный период; при экспорте показывается в денежном выражении | Для учёта затрат команды, распределения по проектам и выявления аномального расхода |
| Доля попаданий в кэш | Строки групп и токенов | Доля попаданий в кэш = токены из кэша / все токены | Чем выше, тем дешевле: токены из кэша обычно тарифицируются по сниженной цене или бесплатно |
| Кэш-токены | Строки групп и токенов | Число токенов, взятых из кэша за выбранный период | Обычно тарифицируются со значительной скидкой — чем их больше, тем больше экономия |
| Запросы с кэшем | Строки групп и токенов | Число запросов, хотя бы раз попавших в кэш | Показывает, сколько запросов действительно использовали кэш |
| Доля запросов с кэшем | Строки групп и токенов | Доля запросов с кэшем = запросы с попаданием в кэш / все запросы | Чем выше, тем больше вызовов получили скидку за кэш |
| Среднее кэш-токенов | Строки групп и токенов | Среднее число токенов из кэша на одно попадание | Для сравнения эффективности кэша у разных участников, сервисов или групп |
| Среднее время | Строки групп и токенов | Среднее время выполнения запроса в секундах | Чем меньше, тем быстрее отвечает upstream-провайдер; при росте проверьте длинный контекст, длинный вывод и цепочки вызовов инструментов |
| Время начала | Строки групп и токенов | Когда группа или токен впервые появились за выбранный период | Помогает определить, когда начались проблема или вызовы |
| Последний запрос | Строки групп и токенов | Когда группа или токен в последний раз появлялись за выбранный период | Помогает понять, продолжаются ли проблема или вызовы |
| Причины сбоев | Строки групп | Самые частые причины сбоев с кодами состояния и числом случаев; при отсутствии ошибок поле пустое или `-` | В первую очередь разбирайте самые частые ошибки, а не только последнюю запись журнала |

<Callout type="info" title="Источник данных">
  Поля формируются агрегированием статистики на стороне сервера. В повседневной работе ориентируйтесь на столбцы списка в консоли и CSV-экспорта; сопоставлять их с исходными именами полей нужно только при интеграции через API или технической диагностике.
</Callout>

<Callout type="idea" title="Поиск причины в команде">
  Сначала по строкам групп определите, не в пуле ли ресурсов проблема, затем по строкам токенов — не вызвана ли она конкретным пользователем или токеном. Если успешность группы в норме, а у одного токена много ошибок, обычно сначала стоит проверить токен этого участника, название модели, настройки клиента или тело запроса.
</Callout>

## Экспорт в CSV

CSV-экспорт выгружает текущий список с теми же столбцами. Он пригодится компаниям и командам для еженедельных отчётов, распределения затрат, разбора инцидентов и сверки использования по участникам.

Экспортированный файл можно открыть в [онлайн-просмотрщике CSV](https://tools.beer/zh/csv/viewer/). Он принимает CSV-файл перетаскиванием или через выбор файла, а также вставленный CSV-текст, поэтому удобен для быстрой проверки содержимого столбцов и причин сбоев.

| Что в экспорте | Описание |
| - | - |
| Строки групп | `Тип` равен `Группа`; ID пользователя, имя пользователя и токен обычно пусты — это сводка по группе |
| Строки токенов | `Тип` равен `Токен`; указаны ID пользователя, имя пользователя и название токена — это детализация по участникам или токенам группы |
| Формат сумм | `Расход` показывается в денежном формате консоли, например `¥905.48` |
| Формат процентов | Успешность, доля попаданий в кэш и доля запросов с кэшем выгружаются в процентах |
| Формат чисел | Большие числа могут содержать разделители разрядов — их удобно читать или импортировать в табличные редакторы |
| Формат времени | «Время начала» и «Последний запрос» выгружаются в местном времени, чтобы их было проще сопоставить со временем возникновения проблемы |
| Причины сбоев | Несколько частых ошибок объединяются, а в конце указывается число случаев; при отсутствии ошибок поле пустое или `-` |

## Порядок диагностики

### 1. Оцените масштаб проблемы

Сначала посмотрите сводные строки с `Тип=Группа`. Если «Успешность» близка к обычному уровню, а значение «Ошибки» невелико, обычно это случайный сбой: скопируйте `request_id` отдельного запроса и продолжайте диагностику.

Если «Успешность» какой-то группы заметно ниже, чем у других групп, или «Ошибки» резко растут, в первую очередь проверьте на уровне группы модель, токены, аккаунты upstream-провайдера, права тарифа и состояние ресурсов платформы.

В компании или команде затем посмотрите строки детализации с `Тип=Токен` в этой группе. Если проблема только у одного пользователя или токена, сначала проверьте настройки клиента этого участника, токен, название модели, тело запроса и стратегию параллельных запросов.

### 2. Изучите самые частые причины ошибок

«Причины сбоев» обычно упорядочены по числу случаев. Начинайте с самых частых ошибок, затем переходите к редким. Частые ошибки показывают основной тип сбоев за выбранный период.

| Тип ошибки | Типичные ключевые слова в журнале | Предварительная причина | Что проверить в первую очередь |
| - | - | - | - |
| Ограничение частоты | `Account RPM limit exceeded`, `Max 10/min`, `Max 5/min` | Проблема использования или ограничение upstream-провайдера | Слишком много параллельных запросов или запросов в минуту |
| Дневной лимит | `Account daily limit exceeded` | Ограничение upstream-провайдера | Дневная квота аккаунта upstream-провайдера на сегодня исчерпана |
| Охлаждение учётных данных | `All credentials ... are cooling down` | Ограничение upstream-провайдера | Все учётные данные upstream-провайдера для текущей модели находятся в периоде охлаждения |
| Слишком большое тело запроса | `status_code=413`, `openai_error` | Проблема использования | Слишком большие контекст, файлы, изображения или результаты инструментов |
| Права доступа или аутентификация | `401`, `403`, `Invalid API key`, `pending admin approval` | Проблема использования или статус аккаунта | Проблемы с токеном, тарифом, группой или правами на модель |
| Нет доступных ресурсов | `No available accounts`, `No available channel`, `auth_unavailable` | Проблема платформы или настройки | В текущей группе нет доступных аккаунтов, каналов или ресурсов аутентификации |
| Сбой upstream-провайдера | `502`, `all upstreams failed`, `Upstream request failed` | Проблема upstream-провайдера | Сбой сервиса upstream-провайдера или промежуточной сети |
| Тайм-аут шлюза | `504`, `521`, `522`, `524` | Проблема upstream-провайдера или сетевого маршрута | Тайм-аут подключения, чтения или ответа upstream-провайдера |
| Защита ресурсов платформы | `system disk overloaded`, `Service Unavailable` | Проблема платформы | Узел платформы или ресурсы upstream-провайдера временно недоступны |
| Формат запроса к API изображений | `gpt-image-2`, `prompt is required`, `multipart form` | Проблема использования | Неверный путь эндпоинта изображений, промпт или формат загрузки |
| Формат вызова инструментов | `tool_use`, `tool_result`, `Invalid schema` | Проблема использования | Сообщения инструментов клиента или JSON Schema не соответствуют требованиям |

### 3. Действуйте по масштабу проблемы

| Симптом | Наиболее вероятная причина | Что делать |
| - | - | - |
| Ошибки только у одного токена | Настройки токена, права доступа или формат локального запроса | Заново скопируйте токен, проверьте настройки клиента и тело запроса |
| Ошибки только у одной модели | Права на модель, канал модели или ресурсы модели у upstream-провайдера | Переключитесь на аналогичную модель и проверьте, поддерживает ли её текущий тариф |
| Низкая успешность только у одной группы | Пул ресурсов группы, права тарифа или аккаунты upstream-провайдера | Смените группу или модель; при обращении в поддержку укажите название группы и период |
| В нескольких группах одновременно `502`, `504`, `521`, `522`, `524` | Сбой upstream-провайдера или сетевого маршрута | Повторите позже и сократите длительные задачи; если ошибки не прекращаются, обратитесь в поддержку |
| `413` во многих запросах | Слишком большое тело запроса | Сократите контекст, разделите файлы, сожмите изображения или уменьшите результаты инструментов |
| `429` во многих запросах | Слишком частые запросы, исчерпанная дневная квота или охлаждение учётных данных | Снизьте параллелизм; по журналу отличайте RPM, daily limit и cooling down |

### 4. Учитывайте расход и кэш

| Симптом | Наиболее вероятная причина | Что делать |
| - | - | - |
| «Расход» заметно выше, чем у других токенов группы | Большой контекст, длинный вывод, частые вызовы или повторяющиеся задачи | Сопоставьте число запросов, среднее время и журнал ошибок, чтобы найти конкретный сервис или участника |
| «Доля попаданий в кэш» высокая, а «Доля запросов с кэшем» низкая | В кэш попадает небольшое число крупных запросов | Проверьте, не переиспользуют ли контекст только отдельные постоянные задачи |
| «Доля запросов с кэшем» высокая, а «Среднее кэш-токенов» низкое | Многие запросы попадают в кэш, но выгода от каждого невелика | Проверьте, не слишком ли короткий контекст и стабильно ли кэшируемое содержимое |
| У одного токена заметно выше «Среднее время» | Тяжёлые задачи клиента, длинный контекст или вывод, медленный upstream-провайдер | Сравните число запросов, кэш, причины сбоев и отдельные записи журнала этого токена |

## Что сообщить в поддержку

С простыми проблемами сначала попробуйте разобраться самостоятельно с помощью страниц [Журнал ошибок](/ru/error-logs) и [Состояние групп](/ru/group-health). Если это не помогло, откройте подробности ошибки в журнале ошибок в `usage-logs/common` и нажмите значок копирования — данные для диагностики скопируются одним кликом. При обращении в поддержку сразу передайте техническим специалистам следующие сведения, чтобы не тратить время на уточнения:

- ID пользователя
- Период: когда проблема началась и когда проявилась в последний раз
- Название группы: `group`
- Название модели: модель, использованная в запросе
- Код состояния: например, `429`, `413`, `502`, `503`
- Текст ошибки: `error_reasons.content`
- ID запроса: `request_id` из записи журнала или ответа API
- Масштаб: один токен, одна модель, одна группа или сбой сразу в нескольких группах

<Callout type="idea" title="Краткий итог">
  При `401` / `403` проверяйте права доступа, при `413` — тело запроса, при `429` — частоту запросов и квоту, при `502` / `504` / `524` — upstream-провайдера и длительные задачи, при `503` — не стали ли ресурсы временно недоступны.
</Callout>
