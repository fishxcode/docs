O FishXCode é uma plataforma de acesso a modelos de IA e serviços de contas tudo-em-um, cobrindo Claude, Codex, Kiro, Grok, modelos chineses e multimodais. Esta página explica como a cobrança funciona, quais grupos existem, como escolher um grupo e como conferir o consumo após o uso.

<Callout type="idea" title="Priorize as informações em tempo real do site">
  Os multiplicadores dos grupos, a disponibilidade de modelos e a situação de recursos mudam conforme ajustes do upstream. A fonte final é a [página de preços](https://fishxcode.com/pricing) e as informações em tempo real do console.
</Callout>

## 1. Duas formas de cobrança

| Forma | Como é cobrado | Adequada para |
| - | - | - |
| Saldo por consumo | Cobra o preço do modelo multiplicado pelo multiplicador do grupo da chave, deduzido do saldo da conta | Chamadas diárias, uso misto de vários modelos, testes pontuais |
| Pacote mensal do pool de contas Codex Pro | Chamadas com chaves criadas no grupo `codex-sub-june`, deduzidas da cota do pacote mensal conforme o consumo real de Tokens | Programação Codex de alta frequência e desenvolvimento de Agentes |

Preços, cotas e modo de uso do pacote mensal: veja [Planos de assinatura](/pt/subscription-plans).

## 3. Como o multiplicador é calculado

O multiplicador é um coeficiente aplicado sobre o preço base do modelo. Quanto menor o multiplicador, menos se cobra pelo mesmo modelo na mesma requisição:

```text
Consumo real ≈ consumo base do modelo × multiplicador do grupo
```

| Consumo base do modelo | Grupo | Dedução estimada |
| - | - | - |
| 10 de cota | `codex-team` (0.15x) | 1,5 de cota |
| 10 de cota | `codex-plus` (0.2x) | 2 de cota |
| 10 de cota | `claude` (1.5x) | 15 de cota |
| 10 de cota | `claudemax` (2.6x) | 26 de cota |

O consumo base do modelo não é um valor fixo; varia conforme o comprimento da entrada, o comprimento da saída, acertos de cache e o preço do próprio modelo. Partes com acerto de cache normalmente custam menos.

<Callout type="warn" title="Não olhe apenas o multiplicador">
  O multiplicador não é o único fator de preço. O preço base, o multiplicador de saída e o multiplicador de cache variam muito entre modelos; modelos de imagem e vídeo podem ainda ter preço fixo. Para estimar custos, tome como referência os preços atuais na página de preços ou na lista de modelos do console.
</Callout>

## 4. Escolha o grupo certo ao criar a API Key

Ao criar uma API Key em **Console → Chaves API**, o grupo da chave define o escopo de modelos disponíveis, o multiplicador de cobrança e o pool de recursos de upstream dessa chave — escolha corretamente.

![Escolher grupo ao criar API Key](/img/start/api-v2-06-token-create.png)

Pontos de atenção ao criar a API Key:

- **Grupo**: define quais modelos a chave pode chamar e com qual multiplicador é cobrada. Ao usar o pacote mensal do Codex, é obrigatório escolher `codex-sub-june`.
- **Configuração de cota**: limita quanto esta chave pode consumir no máximo; cota ilimitada não significa isenção de cobrança — ela continua limitada pelo saldo da conta ou pela cota do pacote mensal.
- **Lista de modelos permitidos**: evite restringir sem necessidade, a menos que você realmente queira permitir apenas alguns modelos.
- **Lista de permissões de IP**: adequada para IPs de saída fixos de servidores; use com cautela em desenvolvimento local, para não perder acesso após mudança de IP.

Sintomas comuns de grupo errado:

- O modelo aparece na lista de modelos, mas ao chamar com a chave atual retorna `model not found`, `model not available` ou erro de permissão.
- O modelo é chamável, mas o multiplicador cobrado ou a estabilidade não correspondem à faixa esperada.
- Chaves do pacote mensal e chaves comuns misturadas, fazendo a cota ir para a conta errada ou deixar as estatísticas pouco claras.

## 6. Conferir o consumo real após o uso

Após as chamadas, confira o consumo real pelos registros de **Console → Logs de uso**. Em cenários de equipe, combine com o [Estado de saúde dos grupos](/pt/group-health) para saber se o problema é de uma chave, de um membro ou do grupo inteiro.

![Exemplo de estado de saúde dos grupos](/img/plans/statistics.png)

| Pergunta | Campos a observar |
| - | - |
| Qual grupo tem maior consumo | Grupo, consumo, número de requisições |
| Se apenas um membro apresenta anomalia | Linhas de detalhe de usuário / chave |
| Se o cache está funcionando | Taxa de acerto do cache, Tokens de cache, proporção de requisições com cache |
| Se é um problema do pool de recursos | Taxa de sucesso do grupo, contagem de erros, motivos de falha |
| Se o custo alto vem de contexto longo ou saída grande | Consumo por requisição bem-sucedida, tempo médio, Tokens de cache |

## 7. Observações de uso

1. Cada grupo corresponde a um pool de recursos diferente; escolha conforme seu cenário de uso.
2. O pacote mensal do Codex exige criar a API Key com o grupo `codex-sub-june`; outros grupos não utilizam a cota desse plano.
3. O pacote mensal não é cota ilimitada; após esgotar a cota ou vencer o plano, não é possível continuar usando.
4. Para conversas longas com Claude, aproveite bem o cache de contexto; o acerto real de cache depende da configuração do cliente, do modelo e do intervalo entre requisições.
5. Multiplicadores de grupo, disponibilidade de modelos e situação de recursos seguem as informações em tempo real do site.

## 8. Investigar anomalias de consumo ou permissão

Ao encontrar consumo anômalo ou modelo indisponível, recomenda-se investigar nesta ordem:

1. Confirme se o grupo vinculado à chave atual inclui o modelo desejado.
2. Confirme o saldo da conta, ou a validade e cota restante do pacote mensal.
3. Abra **Console → Logs de uso** e filtre por hora, modelo, chave, grupo, ID de requisição etc.
4. Compare com o [Estado de saúde dos grupos](/pt/group-health) para distinguir problema de uma chave individual ou do pool de recursos do grupo.
5. Se ainda não for possível determinar, contate o suporte informando número do pedido, nome da chave, grupo, nome do modelo, horário da requisição e ID da requisição.
