O FishXCode é uma plataforma tudo em um de acesso a modelos de IA e serviços de contas, que cobre Claude, Codex, Kiro, Grok, modelos chineses e modelos multimodais. Esta página explica como funciona a cobrança, quais grupos existem, como escolher um grupo e como conferir o consumo depois do uso.

<Callout type="idea" title="Prevalecem as informações em tempo real">
  Os multiplicadores dos grupos, a disponibilidade dos modelos e a situação dos recursos mudam conforme os ajustes dos recursos upstream. A referência final são as informações em tempo real da [página de preços](https://fishxcode.com/pricing) e do console.
</Callout>

## 1. Duas formas de cobrança

| Forma | Como é cobrado | Ideal para |
| - | - | - |
| Pagamento por uso com saldo | Preço do modelo vezes o multiplicador do grupo do token, descontado do saldo da conta | Chamadas do dia a dia, uso combinado de vários modelos e testes pontuais |
| Pacote mensal do pool Codex Pro | As chamadas usam um token criado no grupo `codex-sub-june`, e o consumo real de tokens é descontado do crédito do pacote mensal | Programação intensiva com Codex e desenvolvimento de agentes |

Veja preço, crédito e forma de uso do pacote mensal em [Planos de assinatura](/pt/subscription-plans).

## 3. Como o multiplicador é calculado

O multiplicador é o coeficiente aplicado sobre o preço base do modelo. Quanto menor ele for, menos é descontado pela mesma requisição ao mesmo modelo:

```text
Consumo real ≈ consumo base do modelo × multiplicador do grupo
```

| Consumo base do modelo | Grupo | Dedução estimada |
| - | - | - |
| 10 créditos | `codex-team` (0.15x) | 1.5 créditos |
| 10 créditos | `codex-plus` (0.2x) | 2 créditos |
| 10 créditos | `claude` (1.5x) | 15 créditos |
| 10 créditos | `claudemax` (2.6x) | 26 créditos |

O consumo base do modelo não é um valor fixo: ele varia com o tamanho da entrada e da saída, os acertos de cache e o preço do próprio modelo. A parte atendida pelo cache costuma ser mais barata.

<Callout type="warn" title="Não olhe só para o multiplicador">
  O multiplicador não é o único fator do preço. O preço base, o multiplicador de saída e o multiplicador de cache variam muito entre modelos, e modelos de imagem e vídeo podem ter preço fixo. Para estimar custos, tome como referência o preço atual da página de preços ou da lista de modelos do console.
</Callout>

## 4. Escolha o grupo certo ao criar o token

Ao criar um token em **Console → Gerenciamento de tokens**, o grupo do token define os modelos disponíveis dessa Key, o multiplicador de cobrança e o pool de recursos upstream, por isso escolha com cuidado.

![Seleção do grupo ao criar um token](/img/start/api-06-token-create.png)

Ao criar o token, confira principalmente:

- **Grupo de tokens**: define quais modelos essa Key pode chamar e com qual multiplicador ela é cobrada. Para usar o pacote mensal Codex, é obrigatório escolher `codex-sub-june`.
- **Limite de crédito**: limita o crédito máximo que essa Key pode consumir. Crédito ilimitado não significa que não há cobrança: o uso continua limitado pelo saldo da conta ou pelo crédito do pacote mensal.
- **Lista de restrição de modelos**: não é recomendado restringir sem necessidade, a menos que você queira permitir apenas alguns modelos específicos.
- **Lista de IPs permitidos**: indicada para servidores com IP de saída fixo. Use com cautela no desenvolvimento local, pois se o seu IP mudar as chamadas deixarão de funcionar.

Sintomas comuns de um grupo escolhido errado:

- O modelo aparece na lista de modelos, mas a chamada com a Key atual retorna `model not found`, `model not available` ou erro de permissão.
- O modelo pode ser chamado, mas o multiplicador de cobrança ou a estabilidade não são os esperados.
- Tokens do pacote mensal e tokens comuns são usados juntos, fazendo o crédito ser descontado da conta errada ou deixando as estatísticas confusas.

## 5. Recomendações para escolher o grupo

| Cenário de uso | Recomendação | Descrição |
| - | - | - |
| Programação diária com Codex | `codex-plus` (0.2x) | Ideal para o desenvolvimento de código no dia a dia |
| Codex com multiplicador baixo | `codex-team` (0.15x) | Para quem aceita um pool de recursos compartilhado |
| Uso intensivo de Codex / desenvolvimento de agentes | Pacote mensal do pool Codex Pro | Escolha o pacote mensal de 200 ou 2000 USD de crédito conforme o seu uso real |
| Programação com Claude e tarefas longas | `claude` (1.5x) | Para uso intensivo, considere `claudemax` (2.6x) |
| Kiro | `kiro-svip` (0.2x) | Pool de contas oficiais Kiro de preço integral |
| Modelos chineses | `china` (0.8x) | Conexão direta às APIs oficiais |
| Modelos Grok | `grok` (0.5x) | Grupo exclusivo do xAI Grok |
| Geração de imagem, vídeo e áudio | `fishxlab` (2x) | Consulte no site os modelos e a cobrança específicos |
| Separação por equipe ou projeto | Crie um token separado para cada membro ou projeto | Facilita o controle de crédito, o rateio de custos e o diagnóstico pelos logs |

## 6. Confira o consumo real após o uso

Depois das chamadas, confira o consumo real pelos registros em **Console → Logs de uso**, que são a referência. Em equipes, use também o [Status de saúde dos grupos](/pt/group-health) para saber se o problema está em uma única Key, em um único membro ou no grupo inteiro.

![Exemplo do status de saúde dos grupos](/img/plans/statistics.png)

| Pergunta | Quais campos olhar |
| - | - |
| Qual grupo consome mais | Grupo, Consumo, Requisições |
| Se apenas um membro apresenta anomalia | Linhas de detalhe de usuário / token |
| Se o cache está funcionando | Taxa de cache, Tokens em cache, Proporção de requisições em cache |
| Se é problema do pool de recursos | Taxa de sucesso do grupo, Erros, Motivo da falha |
| Se o custo alto vem de contexto longo ou saída grande | Consumo por requisição bem-sucedida, Tempo médio, Tokens em cache |

## 7. Observações de uso

1. Cada grupo corresponde a um pool de recursos diferente; escolha conforme o seu cenário de uso.
2. Para o pacote mensal Codex, o token precisa ser criado no grupo `codex-sub-june`; os outros grupos não usam o crédito desse pacote.
3. O pacote mensal não tem crédito ilimitado: quando o crédito acaba ou o pacote expira, não é mais possível continuar usando.
4. Em conversas longas com o Claude, aproveite o cache de contexto. Os acertos de cache reais dependem da configuração do cliente, do modelo e do intervalo entre as requisições.
5. Multiplicadores dos grupos, disponibilidade dos modelos e situação dos recursos seguem as informações em tempo real do site.

## 8. Diagnosticar consumo anormal ou problemas de permissão

Se houver consumo anormal ou modelo indisponível, verifique nesta ordem:

1. Confirme se o grupo vinculado à Key atual inclui o modelo desejado.
2. Confirme se o saldo da conta, ou a validade e o crédito restante do pacote mensal, são suficientes.
3. Veja **Console → Logs de uso** e filtre por período, modelo, Token, grupo e request ID.
4. Compare com o [Status de saúde dos grupos](/pt/group-health) para saber se o problema é de um único token ou do pool de recursos do grupo.
5. Se ainda não for possível identificar, entre em contato com o suporte e informe o número do pedido, o nome do token, o grupo, o nome do modelo, o horário da requisição e o request ID.
