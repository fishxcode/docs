## 全般

### FishXCode とは何ですか？

FishXCode は AI モデル接続とアカウントサービスのワンストッププラットフォームです。Claude・Codex・Kiro・Grok・中国系モデル・マルチモーダルモデルに対応し、さまざまなツールやプラットフォームで利用できます。

### どのツールに対応していますか？

現在、次のツールに対応しています：

- **Claude Code** — Anthropic 公式の CLI
- **OpenAI Codex** — OpenAI 公式のプログラミングアシスタント
- **RooCode** — VS Code 用の AI プログラミング拡張機能
- **Qwen Code** — Alibaba の通義千問（Qwen）によるプログラミングツール
- **Droid CLI** — 軽量な AI プログラミング CLI
- **OpenCode** — オープンソースの AI プログラミング用ターミナルツール

### データのプライバシーはどのように守られていますか？

FishXCode は API の中継サービスとしてのみ機能し、お客様のコードや会話内容を保存しません。すべてのリクエストは、対応するモデルプロバイダーに直接転送されます。

<Callout type="idea" title="おすすめ">
  機密性の高いプロジェクトでは、利用前に各モデルプロバイダーのプライバシーポリシーを確認することをおすすめします。
</Callout>

## アカウントとトークン

### 登録するには？

[fishxcode.com/register](https://fishxcode.com/register?aff=9CTW) にアクセスし、案内に従って登録を完了してください。

### API トークンを取得するには？

登録後にコンソールへログインし、[トークン管理ページ](https://fishxcode.com/console/token) で新しいトークンを作成します。

### トークンの有効期間はどれくらいですか？

トークンは、手動で削除または再生成するまで有効です。セキュリティのため、定期的にローテーションすることをおすすめします。

### 利用枠はどれくらいですか？

FishXCode は各ユーザーに利用枠を提供しており、具体的な量はプラットフォームのリソースに応じて動的に調整されます。コンソールに表示される利用状況をご確認ください。

<Callout type="warn" title="注意">
  利用枠を使い切ると、リクエストは拒否されます。計画的にご利用ください。
</Callout>

## ツールの設定

### 環境変数を設定しても反映されない場合は？

次のよくある原因を確認してください：

1. **ターミナルを再起動していない** — `.bashrc` / `.zshrc` を変更した後は、`source ~/.bashrc` を実行するか、新しいターミナルを開く必要があります
2. **変数名のスペルミス** — 大文字と小文字は区別されます。たとえば `ANTHROPIC_BASE_URL` を `Anthropic_Base_Url` と書くことはできません
3. **余分な引用符や空白** — `export KEY="value"` の value の前後に余分な空白を入れないでください

<Accordions type="single">
  <Accordion title="すぐに確認できるコマンド">
    ```bash
    # 変数が設定されているか確認
    echo $ANTHROPIC_BASE_URL
    echo $ANTHROPIC_AUTH_TOKEN

    # 空の場合は、変数が反映されていません
    ```
  </Accordion>
</Accordions>

### 設定ファイルの場所は？

| ツール | 設定ファイルのパス |
| - | - |
| Claude Code | 環境変数で設定 |
| Codex | `~/.codex/config.toml` と `~/.codex/auth.json` |
| RooCode | VS Code の設定 JSON |
| Qwen Code | 環境変数で設定 |

### FishXCode のサービスに接続できない場合は？

1. `BASE_URL` が `https://api.fishxcode.com/` に設定されているか確認します（末尾の `/` に注意）
2. ネットワークから `fishxcode.com` にアクセスできるか確認します
3. 社内ネットワークを使っている場合は、プロキシ設定が正しいか確認します

## モデルの選択

### 適切なモデルを選ぶには？

利用シーンに応じて選んでください：

| シーン | おすすめモデル | 理由 |
| - | - | - |
| 日常的なプログラミング | `claude-sonnet-4-5-20250929` | 能力と速度のバランスがよい |
| 高速な補完 | `claude-3-5-haiku-20241022` | 応答速度が速い |
| 複雑なアーキテクチャ | `claude-sonnet-4-5-20250514` | 推論能力が高い |

### モデルごとの違いは？

- **Sonnet シリーズ**：能力のバランスがよく、ほとんどのプログラミングタスクに適しています
- **Haiku シリーズ**：軽量かつ高速で、簡単な補完や整形のタスクに適しています
- 具体的なモデルの能力の違いは、各プロバイダーの公式ドキュメントを参照してください

### モデルを切り替えるには？

環境変数 `ANTHROPIC_MODEL` で指定します：

```bash
export ANTHROPIC_MODEL=claude-sonnet-4-5-20250929
```

## トラブルシューティング

### 認証失敗（Auth Error）と表示される

<Callout type="warn" title="よくある原因">
  - トークンの入力ミス（余分な空白がある、または不完全）
  - トークンが削除または再生成されている
  - `API_KEY` と `AUTH_TOKEN` が両方そろって設定されていない
</Callout>

解決方法：[コンソール](https://fishxcode.com/console/token) でトークンの状態を確認し、コピーして貼り付け直してください。

### エラーログの確認方法と読み方は？

[コンソール → 使用ログ](https://fishxcode.com/console/log) を開き、ログの種類を **エラーログ** に切り替えると、時刻、モデル、トークン、グループ、リクエスト ID、エラーメッセージ、ステータスコードで絞り込めます。

<Callout type="idea" title="調査のヒント">
  - まず API レスポンスまたはログの `request_id` をコピーし、使用ログで同じリクエストを完全一致で検索します
  - 「エラーメッセージ」で `content` 内のキーワードを検索します。例：`Invalid token`、`Upstream request failed`
  - 「ステータスコード」で問題の種類をすばやく集計します。例：`400`、`401`、`403`、`413`、`429`、`500`、`502`、`503`、`504`
  - 同じグループで同じエラーが集中して発生している場合は、まずグループ単位で、設定の問題か、利用量の問題か、上流の可用性の問題かを判断します
</Callout>

項目の詳しい説明、ステータスコードの分類、よくあるエラーの一覧は [エラーログ解説](/ja/error-logs) をご覧ください。

### グループ稼働状況の見方は？

グループ稼働状況は、問題が個別のリクエストの異常なのか、特定のプラン、モデル、上流グループに集中した異常なのかを判断するためのものです。まず `success_rate`、`error_count`、`error_reasons` を確認し、次に個々のログの `request_id` とあわせて具体的なリクエストを特定します。

ステータスページの全体、項目の説明、調査の流れは [グループ稼働状況](/ja/group-health) をご覧ください。

### リクエストのタイムアウト（Timeout）

考えられる原因：

1. ネットワークの遅延が大きい
2. リクエストのコンテキストが長すぎて、モデルの処理に時間がかかっている
3. 現在、サービスの負荷が高い

対処：入力コンテキストを減らすか、しばらくしてから再試行してください。

### レート制限や利用枠の制限に達した（Rate Limit）

`429` ステータスコードが返された場合、通常はリクエストの頻度が高すぎることを示します。上流アカウントの 1 日の利用枠を使い切ったか、現在のモデルの認証情報がクールダウン中である可能性もあります。

<Callout type="idea" title="対処方法">
  - リクエストの頻度を下げ、数秒空けてから再試行します
  - スクリプトで間隔を空けずにループして API を呼び出さないようにします
  - 同じトークンを他のプロセスが同時に使っていないか確認します
  - ログに `Max 10/min` または `Max 5/min` が含まれる場合は、表示に従って同時実行数と 1 分あたりのリクエスト数をしきい値未満に下げます
  - ログに `daily limit exceeded` が含まれる場合は、1 日の利用枠のリセットを待つか、利用可能な別のモデル／グループに切り替えます
  - ログに `cooling down` が含まれる場合は、すぐに連続して再試行せず、クールダウンの終了を待つか、一時的にモデルを切り替えます
</Callout>

### モデルが利用できないと返される（Model Not Available）

指定したモデル名が正しいかを確認し、[クイックスタート](/ja/start) のおすすめモデル一覧を参照してください。一部のモデルは、まだ FishXCode で提供されていない可能性があります。
