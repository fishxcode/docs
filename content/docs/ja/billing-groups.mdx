## 1. 2 つの課金方式

| 方式 | 課金の仕組み | 適した用途 |
| - | - | - |
| 残高の従量課金 | モデル価格 × Key が属するグループの倍率をアカウント残高から差し引く | 日常的な呼び出し、複数モデルの併用、一時的なテスト |
| Codex Pro アカウントプール月額パッケージ | `codex-sub-june` グループで作成した Key で呼び出し、実際の Token 消費に応じて月額パッケージの容量から差し引く | 高頻度の Codex コーディングと Agent 開発 |

月額パッケージの価格、容量、利用方法は [サブスクリプションプラン](/ja/subscription-plans) をご覧ください。

## 2. 販売中のグループ

グループは、1 つの API Key がどのモデルを呼び出せるか、どのリソースプールを経由するか、どの倍率で課金されるかを決めます。現在販売中のグループは 10 個です：

### Codex シリーズ

| グループ | 倍率 | 説明 |
| - | - | - |
| `codex-plus` | 0.2x | Codex Plus の公式正価格シリーズのアカウントプール。低倍率で安定して利用でき、日常的な呼び出しに適しています |
| `codex-pro` | 0.4x | Codex Pro の公式正価格シリーズのリソース。性能が安定しており、チームや企業向け |
| `codex-team` | 0.15x | Codex Team の公式シリーズ共有アカウントプール。低倍率の共有リソース |
| `codex-officially` | 2x | OpenAI 公式 API Key のリソース。公式直接続で安定・信頼性が高い |

### Claude シリーズ

| グループ | 倍率 | 説明 |
| - | - | - |
| `claude` | 1.5x | Claude Max 20 の公式正価格アカウントプール。フルスペックの性能で安定した直接続 |
| `claudemax` | 2.6x | Claude Max 20 の千規模アカウントプール。高速アクセス・読み取り専用管理で、手動でのトレース対応に対応 |

### その他のモデル

| グループ | 倍率 | 説明 |
| - | - | - |
| `kiro-svip` | 0.2x | Kiro の公式正価格アカウントプール。安定した接続で低倍率 |
| `china` | 0.8x | 中国産主要モデルのコレクション。公式 API 直接続 |
| `grok` | 0.5x | xAI Grok モデル専用グループ。低倍率で Grok の能力を体験できます |

その他のモデルと対応状況の詳細は、サイト内でご確認ください。

<Callout type="info" title="月額パッケージ専用グループ">
  `codex-sub-june` は Codex Pro アカウントプール月額パッケージの専用グループで、倍率は固定 1x、月額パッケージの容量のみから差し引かれ、上記の従量課金グループには含まれません。
</Callout>

## 3. 倍率の計算方法

倍率は、モデルの基本価格にさらに掛ける係数です。倍率が低いほど、同じモデル・同じリクエストでも課金は少なくなります：

```text
実際の消費 ≒ モデル基本消費 × グループ倍率
```

| モデル基本消費 | グループ | 消費の見積もり |
| - | - | - |
| 10 クォータ | `codex-team`（0.15x） | 1.5 クォータ |
| 10 クォータ | `codex-plus`（0.2x） | 2 クォータ |
| 10 クォータ | `claude`（1.5x） | 15 クォータ |
| 10 クォータ | `claudemax`（2.6x） | 26 クォータ |

ここでのモデル基本消費は固定値ではなく、入力長・出力長・キャッシュヒット・モデル自体の価格により変動します。キャッシュヒット部分は通常より安くなります。

<Callout type="warn" title="倍率だけを見ないこと">
  倍率は価格のすべてではありません。モデルごとに基本価格・出力倍率・キャッシュ倍率の差は大きく、画像や動画モデルは固定価格の場合もあります。コストを見積もる際は、料金ページまたはコンソールのモデル一覧にある現在の価格を基準にしてください。
</Callout>

## 4. API Key 作成時に正しいグループを選ぶ

**コンソール → API キー**で API Key を作成する際、Key のグループがその Key の利用可能モデルの範囲、課金倍率、上流リソースプールを決めます。必ず正しく選んでください。

![API Key 作成時のグループ選択](/img/start/api-v2-06-token-create.png)

API Key 作成時に注目すべきポイント：

- **グループ**：この Key がどのモデルを呼び出せるか、どの倍率で課金されるかを決めます。Codex 月額パッケージを使う場合は必ず `codex-sub-june` を選択します。
- **クォータ設定**：この Key が消費できる最大クォータを制限します。無制限クォータでも課金は免除されず、アカウント残高または月額パッケージの容量制限を受けます。
- **モデル制限リスト**：必要でなければ設定しないことを推奨します。特定のいくつかのモデルだけを許可したい場合のみ設定してください。
- **IP ホワイトリスト**：サーバー側の固定グローバル IP 向けです。個人ローカル開発では IP 変更後に呼び出せなくなるため注意してください。

グループを誤って選んだ場合の典型的な症状：

- モデル一覧にはモデルが表示されるのに、現在の Key で呼び出すと `model not found`、`model not available` または権限エラーになる。
- モデルは呼び出せるが、課金倍率や安定性が期待した水準と異なる。
- 月額パッケージの Key と通常の Key を混在させた結果、容量が別のアカウントへ流れたり、統計の集計範囲が不明瞭になったりする。

## 5. グループ選びの推奨

| 利用シーン | 推奨 | 説明 |
| - | - | - |
| 日常の Codex コーディング | `codex-plus`（0.2x） | 日常の開発に適しています |
| 低倍率の Codex | `codex-team`（0.15x） | 共有リソースプールを受け入れられるユーザー向け |
| 高頻度の Codex / Agent 開発 | Codex Pro アカウントプール月額パッケージ | 実際の使用量に応じて 200 または 2,000 米ドルの月額パッケージを選択 |
| Claude のコーディングと長時間タスク | `claude`（1.5x） | 高頻度利用の場合は `claudemax`（2.6x）も検討可 |
| Kiro | `kiro-svip`（0.2x） | Kiro の公式正価格アカウントプール |
| 中国産モデル | `china`（0.8x） | 公式 API 直接続 |
| Grok モデル | `grok`（0.5x） | xAI Grok 専用グループ |
| 画像・動画・音声の生成 | `fishxlab`（2x） | 具体的なモデルと課金はサイト内の情報が優先 |
| チームやプロジェクトの分離 | メンバーまたはプロジェクトごとに独立した API Key を作成 | クォータ管理、コスト配分、ログ調査がしやすくなります |

## 6. 利用後の実際の消費を確認する

呼び出し後は、**コンソール → 使用ログ**の記録を基準に実際の消費を確認します。チーム環境では、[グループの健全性状態](/ja/group-health) と組み合わせて、問題が単一の Key、単一のメンバー、またはグループ全体のどれに由来するかを判断します。

![グループの健全性状態の例](/img/plans/statistics.png)

| 確認したいこと | 見るべきフィールド |
| - | - |
| どのグループの消費が最も高いか | グループ、消費、リクエスト数 |
| 特定のメンバーだけ異常かどうか | ユーザー / Key の明細行 |
| キャッシュが効いているかどうか | キャッシュヒット率、キャッシュ Tokens、キャッシュリクエスト比率 |
| リソースプールの問題かどうか | グループ成功率、エラー数、失敗理由 |
| 長いコンテキストや大きな出力による高額化かどうか | 1 回あたりの成功消費、平均処理時間、キャッシュ Tokens |

## 7. 利用上の注意事項

1. グループごとにリソースプールが異なります。利用シーンに応じて選択してください。
2. Codex 月額パッケージは必ず `codex-sub-june` グループで API Key を作成します。他のグループではこのプランの容量を利用できません。
3. 月額パッケージは無制限ではありません。容量を使い切った場合やプランの期限が切れた場合は利用を続けられません。
4. Claude の長い会話では、コンテキストキャッシュを適切に活用してください。実際のキャッシュヒットはクライアント設定、モデル、リクエスト間隔に依存します。
5. グループの倍率、モデルの利用可否、リソース状況はサイト内のリアルタイム情報が優先されます。

## 8. 消費や権限の異常を調査する

消費の異常やモデルの利用不可に遭遇した場合は、次の順序で調査することを推奨します：

1. 現在の Key に紐づくグループに、対象モデルが含まれているか確認する。
2. アカウント残高、または月額パッケージの有効期間と残り容量が十分か確認する。
3. **コンソール → 使用ログ**を開き、時間、モデル、Key、グループ、リクエスト ID で絞り込む。
4. [グループの健全性状態](/ja/group-health) と比較し、単一の Key の問題か、グループのリソースプールの問題かを判断する。
5. それでも判断できない場合は、注文番号、Key 名、グループ、モデル名、リクエスト時刻、リクエスト ID を添えてサポートへご連絡ください。
