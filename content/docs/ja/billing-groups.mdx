FishXCode は、AI モデルへの接続とアカウントサービスをワンストップで提供するプラットフォームです。Claude、Codex、Kiro、Grok、中国製モデル、マルチモーダルモデルに対応しています。このページでは、課金のしくみ、用意されているグループとその選び方、利用後に消費を照合する方法を説明します。

<Callout type="idea" title="サイト上のリアルタイム情報が優先されます">
  グループの倍率、モデルの利用可否、リソースの状況は上流リソースに応じて調整されます。最終的には [料金ページ](https://fishxcode.com/pricing) とコンソールのリアルタイム情報が優先されます。
</Callout>

## 1. 課金方式は 2 種類

| 方式 | 課金のしくみ | 向いている場面 |
| - | - | - |
| 残高による従量課金 | モデル価格にトークンが属するグループの倍率を掛けて計算し、アカウント残高から差し引く | 日常的な呼び出し、複数モデルの併用、一時的なテスト |
| Codex Pro アカウントプール月額パック | `codex-sub-june` グループで作成したトークンで呼び出し、実際のトークン消費量に応じて月額パックの利用枠から差し引く | 高頻度の Codex プログラミングと Agent 開発 |

月額パックの価格、利用枠、使い方は [サブスクリプションプラン](/ja/subscription-plans) をご覧ください。

</Callout>

## 3. 倍率の計算方法

倍率は、モデルの基本価格にさらに掛ける係数です。倍率が低いほど、同じモデル・同じリクエストでの差し引き額は少なくなります：

```text
実際の消費 ≈ モデルの基本消費 × グループ倍率
```

| モデルの基本消費 | グループ | 差し引き額の目安 |
| - | - | - |
| 10 クレジット | `codex-team`（0.15x） | 1.5 クレジット |
| 10 クレジット | `codex-plus`（0.2x） | 2 クレジット |
| 10 クレジット | `claude`（1.5x） | 15 クレジット |
| 10 クレジット | `claudemax`（2.6x） | 26 クレジット |

ここでいうモデルの基本消費は固定値ではなく、入力の長さ、出力の長さ、キャッシュヒット、モデル自体の価格によって変わります。キャッシュにヒットした部分は、通常は割安になります。

<Callout type="warn" title="倍率だけで判断しない">
  倍率は価格を決める唯一の要素ではありません。モデルごとに基本価格、出力倍率、キャッシュ倍率は大きく異なり、画像や動画のモデルは固定価格の場合もあります。コストを見積もる際は、料金ページまたはコンソールのモデル一覧に表示されている現在の価格を基準にしてください。
</Callout>

## 4. トークン作成時に正しいグループを選ぶ

**コンソール → トークン管理** でトークンを作成するときは、トークングループによって、その Key で利用できるモデルの範囲、課金倍率、上流リソースプールが決まります。必ず正しいグループを選んでください。

![トークン作成時のグループ選択](/img/start/api-06-token-create.png)

トークンを作成するときは、次の項目を重点的に確認してください：

- **トークングループ**：この Key で呼び出せるモデルと課金倍率を決めます。Codex の月額パックを使う場合は、必ず `codex-sub-june` を選んでください。
- **利用枠の設定**：この Key で消費できる利用枠の上限を設定します。利用枠を無制限にしても課金されないわけではなく、アカウント残高または月額パックの利用枠による制限は引き続き適用されます。
- **モデル制限リスト**：特定のモデルだけを許可すると決めている場合を除き、制限はおすすめしません。
- **IP ホワイトリスト**：送信元 IP が固定されたサーバー向けです。個人のローカル開発では、IP が変わると呼び出せなくなるおそれがあるため、慎重に使ってください。

グループを間違えた場合によくある症状：

- モデル一覧にはモデルが表示されるのに、現在の Key で呼び出すと `model not found`、`model not available`、または権限エラーが出る。
- モデルは呼び出せるが、課金倍率や安定性が想定していたランクと異なる。
- 月額パック用のトークンと通常のトークンを混用し、利用枠が想定外のアカウントから差し引かれたり、集計基準が不明確になったりする。

| Claude でのプログラミングと長時間のタスク | `claude`（1.5x） | 高頻度で使う場合は `claudemax`（2.6x）も検討できる |

| チームやプロジェクトで分けたい | メンバーやプロジェクトごとに個別のトークンを作成 | 利用枠の管理、コストの按分、ログでの調査がしやすい |

## 6. 利用後に実際の消費を照合する

呼び出した後は、**コンソール → 使用ログ** の記録を基準に実際の消費を照合してください。チームで利用している場合は、さらに [グループ稼働状況](/ja/group-health) とあわせて、単一の Key、単一のメンバー、グループ全体のどこに問題があるかを判断します。

![グループ稼働状況の例](/img/plans/statistics.png)

| 疑問 | 確認する項目 |
| - | - |
| どのグループの消費が最も多いか | グループ、消費、リクエスト数 |
| 特定のメンバーだけが異常なのか | ユーザー / トークンの明細行 |
| キャッシュが効いているか | キャッシュヒット率、キャッシュトークン数、キャッシュリクエスト率 |
| リソースプールの問題か | グループの成功率、エラー数、失敗原因 |
| 長いコンテキストや大量の出力で費用が高くなっていないか | 1 回の成功あたりの消費、平均所要時間、キャッシュトークン数 |

## 7. 利用上の注意事項

1. グループごとにリソースプールが異なるため、利用シーンに応じて選んでください。
2. Codex の月額パックを使うには、必ず `codex-sub-june` グループでトークンを作成してください。他のグループではこのプランの利用枠を使えません。
3. 月額パックの利用枠は無制限ではありません。利用枠を使い切るか、プランの有効期限が切れると、それ以降は利用できなくなります。
4. Claude で長い対話をする場合は、コンテキストキャッシュを適切に活用することをおすすめします。実際のキャッシュヒットは、クライアントの設定、モデル、リクエストの間隔によって変わります。
5. グループの倍率、モデルの利用可否、リソースの状況は、サイト上のリアルタイム情報が優先されます。

## 8. 消費や権限の異常を調査する

消費の異常やモデルが使えない問題が起きたときは、次の順序で調査することをおすすめします：

1. 現在の Key に紐付いたグループに、目的のモデルが含まれているかを確認します。
2. アカウント残高が十分か、または月額パックが有効期間内で利用枠が十分に残っているかを確認します。
3. **コンソール → 使用ログ** を開き、時刻、モデル、トークン、グループ、リクエスト ID で絞り込みます。
4. [グループ稼働状況](/ja/group-health) と比較し、単一のトークンの問題か、グループのリソースプールの問題かを判断します。
5. それでも判断できない場合は、サポートに連絡し、注文番号、トークン名、グループ、モデル名、リクエスト時刻、リクエスト ID を伝えてください。
