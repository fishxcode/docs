description: FishXCode コンソールのエラーログの項目、ステータスコードの意味、よくあるエラー、トラブルシューティングの流れを説明します。
---

エラーログは、個々のリクエストが失敗した具体的な原因を特定するためのものです。調査の際は、まず使用ログを「グループ」で絞り込んでエラーが同じグループに集中しているかを確認し、次にエラーログの `request_id` で個々のリクエストを特定することをおすすめします。

入口：[コンソール → 使用ログ](https://fishxcode.com/usage-logs/common)。ログの種類を **エラーログ** に切り替えると、時刻、モデル、トークン、グループ、リクエスト ID、エラーメッセージ、ステータスコードで絞り込めます。

<Callout type="idea" title="すばやく判断するには">
  - `request_id` は個々のリクエストの特定に使います
  - `status_code` はエラーの種類ごとの集計に使います
  - `content` は具体的なエラーキーワードの検索に使います
  - `group` は問題が特定のグループに集中しているかの判断に使います
</Callout>

## 項目の説明

| 項目 | 意味 | 調査での役割 |
| - | - | - |
| 時刻 | リクエストが失敗した時刻 | 問題が継続して発生しているかを判断します |
| モデル | リクエストで使用したモデル名 | 特定のモデルだけに影響しているかを判断します |
| トークン | リクエストで使用した API Key またはトークン名 | 特定のトークンだけに影響しているかを判断します |
| グループ | リクエストが属するモデルまたは上流リソースのグループ | グループに集中した異常かどうかを判断します |
| リクエスト ID | 個々のリクエストの一意な識別子。通常は `request_id` | サポートへの問い合わせ時に最優先で伝えます |
| エラーメッセージ | 失敗原因のテキスト。通常は `content` を含みます | キーワードで具体的なエラーを特定します |
| ステータスコード | HTTP または上流のステータスコード。例：`401`、`429`、`502` | エラーをすばやく分類するのに使います |

## 調査の手順

1. API レスポンスまたはログの `request_id` をコピーし、まず個々のリクエストを完全一致で検索します。
2. `request_id` がない場合は、期間、モデル、トークンで範囲を絞り込みます。
3. ステータスコードでエラーの種類を集計します。例：`401`、`413`、`429`、`502`、`503`。
4. エラーメッセージでキーワードを検索します。例：`Invalid API key`、`daily limit exceeded`、`Upstream request failed`。
5. 同じグループで同じエラーが集中して発生している場合は、そのグループのリソースプールが影響を受けている可能性が高いです。しばらくしてから再試行するか、グループを切り替えてください。

## 原因の切り分け

エラーログを使うと、問題が「利用上の問題」「上流の問題」「プラットフォームの問題」のどれに当たるかを一次判定できます。切り分けはステータスコードだけで行わず、影響範囲とあわせて判断します：

| 切り分け | 判断基準 | 典型的な症状 | 優先する対処 |
| - | - | - | - |
| 利用上の問題 | 単一のリクエスト、単一のトークン、または特定のクライアント設定にのみ影響する | リクエストボディの形式エラー、パラメーターの不一致、トークンのコピーミス、コンテキストが大きすぎる、API パスの誤り | ローカル設定、リクエストボディ、モデル名、トークン、ツールのバージョンを確認する |
| 上流の問題 | 複数のリクエストで、上流の失敗、ゲートウェイのタイムアウト、上流の利用制限が集中して発生する | `Upstream request failed`、`all upstreams failed`、`bad response status code 502/524`、上流アカウントのレート制限 | しばらくしてから再試行し、同時実行数を下げる。必要に応じてモデルやグループを切り替える |
| プラットフォームの問題 | プラットフォームのノード、リソースプール、チャネルが利用できない | `system disk overloaded`、`No available accounts`、`No available channel`、プラットフォーム側の `Service Unavailable` | しばらくしてから再試行する。続く場合はグループ、期間、`request_id` を添えてサポートに連絡する |
| グループとあわせて判断 | 単一のログでは責任の所在を正確に判断できない | `429`、`502`、`503` など、複数の原因で発生しうるエラー | ログをグループで絞り込み、集中して発生しているかを確認する |

<Callout type="warn" title="注意">
  1 件の `502` や `503` だけで責任の所在を判断しないでください。単一のリクエストの失敗は、上流の一時的な揺らぎである可能性があります。同じグループで同じ時間帯に大量の失敗が起きている場合に、上流またはプラットフォームのリソースの問題として扱うのが適切です。
</Callout>

## ステータスコードの分類

| ステータスコード | よくある意味 | 一次判定 | 優先する対処 |
| - | - | - | - |
| `400` | リクエストボディの形式、パラメーター、ツールメッセージが要件を満たしていない | 利用上の問題 | クライアントのリクエストボディ、API パス、ツールの schema を確認する |
| `401` | トークンが無効、未有効化、または認証に失敗した | 利用上の問題 | トークンをコピーし直し、トークンの状態を確認する |
| `403` | 上流がアクセスを拒否した。権限やモデルのアクセス制限でよく発生する | 利用上の問題または上流の問題 | グループとモデルの権限を確認する |
| `413` | リクエストボディが大きすぎる | 利用上の問題 | コンテキストを短くし、ファイルを分割し、画像を圧縮する |
| `429` | レート制限、1 日の利用上限、または認証情報のクールダウン | グループとあわせて判断 | 同時実行数を下げ、利用枠の回復またはクールダウンの終了を待つ |
| `500` | 中継レイヤーまたは上流でラップされた内部エラー | エラーメッセージとあわせて判断 | エラーメッセージから実際の原因を判断する |
| `502` | 上流サービスまたは途中のネットワークの異常 | 上流の問題または経路の問題 | しばらくしてから再試行し、必要に応じてモデル／グループを切り替える |
| `503` | サービス、チャネル、アカウント、またはプラットフォームのリソースが一時的に利用できない | 上流の問題またはプラットフォームの問題 | しばらくしてから再試行し、続く場合はサポートに連絡する |
| `504` / `521` / `522` / `524` | ゲートウェイの接続、読み取り、応答のタイムアウト | 上流の問題または経路の問題 | 長時間のタスクを減らし、しばらくしてから再試行する |

## よくあるエラーメッセージ

| エラーログの内容 | 意味 | 一次判定 | 推奨される対処 |
| - | - | - | - |
| `status_code=401, Invalid token` | トークンが無効、コピーミス、または失効している | 利用上の問題 | コンソールのトークンをコピーし直し、余分な空白がないことを確認する |
| `status_code=401, Invalid API key or key is pending admin approval` | API Key が無効、または新しい Key がまだ審査待ち／有効化待ち | 利用上の問題またはアカウントの状態 | コンソールの最新のトークンを使っていることを確認する。作成直後の場合は反映を待ってから再試行し、それでも失敗する場合はサポートに連絡する |
| `status_code=403, bad response status code 403` | 上流が現在のリクエストを拒否した。権限、アカウントの状態、モデルのアクセス制限でよく発生する | 利用上の問題または上流の問題 | トークン、グループ、モデルの権限を確認する。続く場合はモデルを切り替えるか、`request_id` を添えてサポートに連絡する |
| `status_code=413, openai_error` / `bad response status code 413` | リクエストボディが大きすぎる。コンテキスト、ファイル、画像、ツールの結果が大きすぎる場合によく発生する | 利用上の問題 | コンテキストを短くし、一度にアップロードする内容を減らし、大きなファイルを分割するか画像を圧縮してから再試行する |
| `status_code=429, Account RPM limit exceeded` | 上流アカウントが 1 分あたりのリクエスト制限に達した | 利用上の問題または上流の制限 | 同時実行数と再試行の頻度を下げ、しばらくしてから再試行する |
| `status_code=429, Account daily limit exceeded` | 上流アカウントが 1 日あたりのリクエスト上限に達した | 上流の制限 | 1 日の利用枠のリセットを待つか、利用可能な別のモデル／グループに切り替える |
| `status_code=429, All credentials for model ... are cooling down` | 現在のモデルの上流認証情報がすべてクールダウン中 | 上流の制限 | 再試行の頻度を下げ、クールダウンの終了を待つ。急ぎのタスクは一時的にモデルを切り替える |
| `status_code=500, 请求失败 [429]: {"message":"Too many requests, please wait before trying again."}` | 上流は `429` のレート制限を返したが、中継レイヤーで `500` としてラップされた | 利用上の問題または上流の制限 | レート制限として対処する：同時実行数を下げ、再試行の間隔を延ばし、すぐに連続して再試行しない |
| `status_code=500, auth_unavailable: no auth available` | 現在のモデルまたはグループに、一時的に利用可能な上流の認証リソースがない | プラットフォームの問題 | しばらくしてから再試行する。続く場合は利用可能なモデル／グループに切り替えるか、サポートに連絡してグループの状態を確認する |
| `status_code=502, Upstream request failed` / `bad response status code 502` / `all upstreams failed` | 上流サービスまたは途中のネットワークが異常を返した、または利用可能なすべての上流へのリクエストが失敗した | 上流の問題 | しばらくしてから再試行する。続く場合はモデルを切り替えるか、`request_id` を添えてサポートに連絡する |
| `status_code=502, openai_error` | OpenAI 互換の上流が異常を返したが、中継レイヤーではより具体的な原因を取得できなかった | 上流の問題 | まず上流の異常として対処する。同じリクエストで安定して再現する場合は、コンテキストを減らし、`request_id` をサポートに伝える |
| `status_code=502, The origin web server returned an invalid or incomplete response to Cloudflare` | 上流のオリジンサーバーが Cloudflare 経由で異常なレスポンスを返した | 上流の問題 | 通常は一時的な上流の障害のため、しばらくしてから再試行する |
| `status_code=500, upstream error: do request failed` | 上流へのリクエスト送信に失敗した。ネットワーク接続の問題や、上流に一時的に到達できない場合によく発生する | 上流の問題または経路の問題 | しばらくしてから再試行する。続く場合は `request_id` をサポートに伝えて調査を依頼する |
| `status_code=520, bad response status code 520` | Cloudflare が不明なエラーを返した。通常は上流のレスポンス異常や接続の中断を示す | 上流の問題または経路の問題 | しばらくしてから再試行する。集中して発生する場合は上流の障害として対処する |
| `status_code=521` / `522` / `504` / `524` | Cloudflare または上流ゲートウェイでの接続、読み取り、応答のタイムアウト | 上流の問題または経路の問題 | まずしばらくしてから再試行する。長時間のタスクでのみ発生する場合は、コンテキスト、出力の長さ、ツールの呼び出し経路を減らす |
| `status_code=503, Service Unavailable` | 上流サービスが一時的に利用できない、または現在のグループに利用可能なリソースがない | グループとあわせて判断 | しばらくしてから再試行する。続く場合はモデル／グループを切り替えるか、サポートに連絡してリソースの状態を確認する |
| `status_code=503, system disk overloaded` | サービスノードのディスク使用率が高すぎるため、プラットフォームがサービスを保護するために一時的にリクエストを拒否している | プラットフォームの問題 | プラットフォーム側の容量／ノードの状態の問題です。しばらくしてから再試行し、続く場合はサポートに連絡してください |
| `status_code=503, No available accounts: no available accounts` | 現在のグループに利用可能な上流アカウントがない | プラットフォームの問題 | モデル／グループを切り替えるか、しばらくしてから再試行する。長時間続く場合はサポートに連絡してリソースプールを確認する |
| `status_code=503, No available channel for model ... under group ...` | 現在のグループに、そのモデルの利用可能なチャネルがない | 利用上の問題またはプラットフォームの問題 | モデル名とグループの対応範囲を確認し、そのグループが対応しているモデルに切り替える |
| `status_code=503, model gpt-image-2 is only supported on /v1/images/generations and /v1/images/edits` | 画像モデルが誤った API で使われている | 利用上の問題 | 画像の生成／編集リクエストは、対応する images API に送信する |
| `status_code=500, Image source is a local path that is not readable from this server` | リクエストに、上流が現在読み取れないローカルの画像パスが含まれている。ターミナルの入力が反応しなくなることがある | 利用上の問題 | フロントエンドのプロジェクトでは、まず `lock` 系の依存関係ファイルを確認する：該当するロックファイルを削除するか、ロックファイル内の異常な `png` フィールドを削除してからセッションを開き直す。画像の送信を続ける場合は、公開されている `http(s)` の画像 URL を使うか、`data:image/...` の base64 を渡す |
| `status_code=500, failed to parse multipart form` | 画像やファイルのアップロードのリクエストボディが API の要件を満たしていない | 利用上の問題 | `multipart/form-data` のフィールド名、ファイルフィールド、リクエストヘッダーを確認する。boundary を手動で誤って書かないようにする |
| `status_code=400, Invalid request: prompt is required` / `解析 Images 请求失败: prompt 不能为空` | 画像の生成／編集リクエストに `prompt` がない | 利用上の問題 | 空でない `prompt` を指定し、リクエストが画像 API に送られていることを確認する |
| `status_code=400, Unsupported parameter: messages` | API とパラメーターの形式が一致していない。Chat/Responses のパラメーターを `messages` 非対応の API に送った場合によく発生する | 利用上の問題 | 現在のツールの `base_url`、API パス、モデルの種類を確認し、対象 API のドキュメントに沿ってリクエストボディを調整する |
| `tool_use ids were found without tool_result blocks immediately after` | ツール呼び出しのメッセージの順序が Claude のプロトコル要件を満たしていない | 利用上の問題 | 各 `tool_use` の直後に、対応する `tool_result` を置く。ツールが自動生成している場合は、クライアントを更新するかセッションを開き直す |
| `Invalid schema for function ... None is not of type 'array'` | ツール関数の schema がモデルの要件を満たしていない。通常は `parameters` や配列フィールドが空、または型が誤っている | 利用上の問題 | MCP／ツールの定義を確認し、配列フィールドには `[]` を指定し、関数パラメーターの schema が JSON Schema に準拠するようにする |
| `status_code=500, not implemented` | 現在の API、モデルの機能、またはツール呼び出しの経路がまだ実装されていない | 利用上の問題またはプラットフォームの問題 | 対応している API とモデルを使っていることを確認する。必要に応じてモデルを切り替えるか、サポートに連絡して互換性を確認する |

## 種類別の対処

### 認証と権限

`401`、`403`、`Invalid API key`、`pending admin approval`、`No available channel` に注目します。まず、トークンがコンソールで発行されたものか、完全にコピーされているか、現在のモデルとグループの権限があるかを確認します。

### リクエスト形式

`400`、`413`、`Unsupported parameter`、`prompt is required`、`Invalid schema` に注目します。まず API パス、リクエストボディのフィールド、ツールの schema、画像リクエストのパラメーター、コンテキストのサイズを確認します。

### レート制限と利用枠

`429`、`Max 10/min`、`daily limit exceeded`、`cooling down` に注目します。間隔を空けずに再試行しないでください。ログに示された制限に合わせて同時実行数を下げるか、利用枠や認証情報の回復を待ちます。

### 上流とプラットフォームのリソース

`502`、`503`、`504`、`520`、`521`、`522`、`524`、`Service Unavailable`、`system disk overloaded` に注目します。まずしばらくしてから再試行し、同じグループで集中して発生している場合は、そのグループのリソースプールが影響を受けているためグループを切り替えてください。

## サポートへの問い合わせに必要な情報

簡単な問題であれば、まず [エラーログ解説](/ja/error-logs) を見て自分で確認することをおすすめします。それでも解決しない場合は、`usage-logs/common` のエラーログ詳細でコピーアイコンをクリックすると、調査用の内容をワンクリックでコピーできます。サポートに連絡する際は、やり取りの回数を減らせるよう、次の情報をまとめて技術担当者に伝えてください：

- ユーザー ID
- 期間：問題が始まった時刻と最後に発生した時刻
- グループ名：`group`
- モデル名：リクエストで使用したモデル
- ステータスコード：`429`、`413`、`502`、`503` など
- エラー内容：`error_reasons.content`
- リクエスト ID：個々のログまたは API レスポンスに含まれる `request_id`
- 影響範囲：単一のトークン、単一のモデル、単一のグループか、複数のグループで同時に異常が起きているか

<Callout type="idea" title="まとめ">
  エラーログは「このリクエストがなぜ失敗したのか」を説明し、グループ稼働状況は「この問題が集中して発生しているのか」を判断します。両方を組み合わせて使うと、最も効率よく調査できます。
</Callout>
