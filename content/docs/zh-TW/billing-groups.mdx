FishXCode 是一站式 AI 模型接入與帳號服務平台，涵蓋 Claude、Codex、Kiro、Grok、國產模型與多模態模型。這頁說明怎麼計費、有哪些分組、怎麼選分組，以及用完後怎麼核對消耗。

<Callout type="idea" title="以站內即時資訊為準">
  分組倍率、模型可用性及資源情況會隨上游資源調整，最終以 [定價頁](https://fishxcode.com/pricing) 和控制台的即時資訊為準。
</Callout>

## 一、兩種計費方式

| 方式 | 怎麼扣費 | 適合 |
| - | - | - |
| 餘額按量 | 按模型價格乘以 Key 所在分組的倍率，從帳戶餘額扣減 | 日常呼叫、多模型混用、臨時測試 |
| Codex Pro 號池月包 | 用 `codex-sub-june` 分組建立的 Key 呼叫，按實際 Token 消耗扣減月包額度 | 高頻 Codex 程式設計與 Agent 開發 |

月包的價格、額度和使用方法見 [訂閱方案](/zh-TW/subscription-plans)。

## 三、倍率怎麼算

倍率是在模型基礎價格上再乘的係數。倍率越低，同一模型同一請求扣得越少：

```text
實際消耗 ≈ 模型基礎消耗 × 分組倍率
```

| 模型基礎消耗 | 分組 | 估算扣除 |
| - | - | - |
| 10 額度 | `codex-team`（0.12x） | 1.2 額度 |
| 10 額度 | `codex-plus`（0.2x） | 2 額度 |
| 10 額度 | `claude`（1.5x） | 15 額度 |
| 10 額度 | `claudemax`（2.6x） | 26 額度 |

這裡的模型基礎消耗不是固定值，會隨輸入長度、輸出長度、快取命中和模型本身的價格變化。命中快取的部分通常更便宜。

<Callout type="warn" title="不要只看倍率">
  倍率不是唯一價格。不同模型的基礎價格、輸出倍率、快取倍率差異很大；圖片、影片模型還可能是固定價格。估算成本時，請以定價頁或控制台模型列表中的目前價格為準。
</Callout>

## 四、建立 API Key 時選對分組

在 **控制台 → API 金鑰** 建立 API Key 時，金鑰分組就是這把 Key 的可用模型範圍、扣費倍率和上游資源池，一定要選對。

![建立 API 金鑰時選擇分組](/img/start/api-v2-06-token-create.png)

建立 API Key 時重點看：

- **分組**：決定這把 Key 能呼叫哪些模型、按什麼倍率扣費。使用 Codex 月包時必須選 `codex-sub-june`。
- **額度設定**：限制這把 Key 最多可消耗多少額度；無限額度不代表不扣費，仍受帳戶餘額或月包額度限制。
- **模型限制清單**：非必要不建議限制，除非你明確只允許某幾個模型。
- **IP 白名單**：適合伺服器固定出口；個人本機開發請謹慎使用，避免 IP 變動後無法呼叫。

分組選錯時，常見表現：

- 模型列表裡看得到模型，但目前 Key 呼叫時回報 `model not found`、`model not available` 或權限錯誤。
- 能呼叫模型，但扣費倍率或穩定性不是預期的那一檔。
- 月包 Key 和一般 Key 混用，導致額度走錯帳戶或統計口徑不清晰。

## 五、分組選擇建議

| 使用情境 | 推薦 | 說明 |
| - | - | - |
| 日常 Codex 程式設計 | `codex-plus`（0.2x） | 適合日常程式碼開發 |
| 低倍率 Codex | `codex-team`（0.12x） | 適合接受共享資源池的使用者 |
| 高頻 Codex / Agent 開發 | Codex Pro 號池月包 | 依實際使用量選擇 200 或 2000 美元額度月包 |
| Claude 程式設計與長任務 | `claude`（1.5x） | 高頻使用可考慮 `claudemax`（2.6x） |
| Kiro | `kiro-svip`（0.2x） | Kiro 官方正價號池 |
| 國產模型 | `china`（0.8x） | 官方 API 直連 |
| Grok 模型 | `grok`（0.5x） | xAI Grok 專屬分組 |
| 圖像、影片、音訊生成 | `fishxlab`（2x） | 具體模型及計費以站內為準 |
| 團隊或專案拆分 | 為成員或專案建立獨立 API Key | 便於額度控制、成本分攤和日誌排查 |

## 六、使用後核對實際消耗

呼叫後以 **控制台 → 使用日誌** 的紀錄為準核對實際消耗。團隊情境下，再結合 [分組健康狀態](/zh-TW/group-health) 判斷是單把 Key、單一成員還是整個分組的問題。

![分組健康狀態範例](/img/plans/statistics.png)

| 問題 | 看哪個欄位 |
| - | - |
| 哪個分組消耗最高 | 分組、消耗、請求數 |
| 是否只有某個成員異常 | 使用者 / Key 明細列 |
| 快取有沒有生效 | 快取命中率、快取 Tokens、快取請求佔比 |
| 是否是資源池問題 | 分組成功率、錯誤數、失敗原因 |
| 是否是長上下文或大輸出導致費用高 | 單次成功消耗、平均耗時、快取 Tokens |

## 七、使用注意事項

1. 不同分組對應不同資源池，請依使用情境選擇。
2. Codex 月包必須使用 `codex-sub-june` 分組建立 API Key，其他分組不適用該方案額度。
3. 月包不是無限額度，額度耗盡或方案到期後將無法繼續使用。
4. Claude 長對話建議合理利用上下文快取，實際快取命中與用戶端設定、模型及請求間隔有關。
5. 分組倍率、模型可用性及資源情況以站內即時資訊為準。

## 八、排查消費或權限異常

遇到消費異常或模型不可用時，建議按這個順序排查：

1. 確認目前 Key 綁定的分組是否包含目標模型。
2. 確認帳戶餘額，或月包的有效期限與剩餘額度是否充足。
3. 查看 **控制台 → 使用日誌**，按時間、模型、Key、分組、請求 ID 篩選。
4. 對照 [分組健康狀態](/zh-TW/group-health)，判斷是單把 Key 的問題還是分組資源池的問題。
5. 仍無法判斷時，聯絡支援並提供訂單號、Key 名稱、分組、模型名、請求時間和請求 ID。
