FishXCode est une plateforme tout-en-un d'accès aux modèles d'IA et de services de comptes, qui couvre Claude, Codex, Kiro, Grok, les modèles chinois et les modèles multimodaux. Cette page explique comment fonctionne la facturation, quels groupes sont disponibles, comment en choisir un et comment vérifier votre consommation après usage.

<Callout type="idea" title="Les informations en temps réel du site font foi">
  Les multiplicateurs des groupes, la disponibilité des modèles et l'état des ressources évoluent au gré des ajustements des ressources amont. Les informations en temps réel de la [page Tarifs](https://fishxcode.com/pricing) et de la console font foi.
</Callout>

## 1. Deux modes de facturation

| Mode | Mode de déduction | Usage conseillé |
| - | - | - |
| Solde à l'usage | Prix du modèle multiplié par le multiplicateur du groupe du token, déduit du solde du compte | Appels quotidiens, usage de plusieurs modèles, tests ponctuels |
| Forfait mensuel du pool Codex Pro | Appels avec un token créé dans le groupe `codex-sub-june`, déduits du crédit du forfait selon la consommation réelle de tokens | Programmation Codex intensive et développement d'agents |

Les prix, le crédit et le mode d'emploi du forfait mensuel sont présentés dans [Abonnements](/fr/subscription-plans).

## 3. Calcul du multiplicateur

Le multiplicateur est un coefficient appliqué au prix de base du modèle. Plus il est bas, moins la même requête sur le même modèle coûte cher :

```text
Coût réel ≈ coût de base du modèle × multiplicateur du groupe
```

| Coût de base du modèle | Groupe | Déduction estimée |
| - | - | - |
| 10 crédits | `codex-team` (0.15x) | 1.5 crédit |
| 10 crédits | `codex-plus` (0.2x) | 2 crédits |
| 10 crédits | `claude` (1.5x) | 15 crédits |
| 10 crédits | `claudemax` (2.6x) | 26 crédits |

Le coût de base du modèle n'est pas une valeur fixe : il varie selon la longueur de l'entrée, la longueur de la sortie, les hits de cache et le prix propre du modèle. La partie servie par le cache est généralement moins chère.

<Callout type="warn" title="Ne vous fiez pas au seul multiplicateur">
  Le multiplicateur ne fait pas le prix à lui seul. Les prix de base, les multiplicateurs de sortie et les multiplicateurs de cache varient fortement d'un modèle à l'autre ; les modèles d'image et de vidéo peuvent aussi être à prix fixe. Pour estimer un coût, référez-vous aux prix actuels de la page Tarifs ou de la liste des modèles de la console.
</Callout>

## 4. Choisir le bon groupe à la création du token

Lorsque vous créez un token dans **Console → Gestion des tokens**, le groupe de tokens définit les modèles accessibles à cette clé, son multiplicateur de facturation et son pool de ressources amont : choisissez-le avec soin.

![Choix du groupe lors de la création d'un token](/img/start/api-06-token-create.png)

Points à vérifier lors de la création du token :

- **Groupe de tokens** : détermine quels modèles cette clé peut appeler et à quel multiplicateur elle est facturée. Pour le forfait mensuel Codex, vous devez choisir `codex-sub-june`.
- **Quota** : limite le crédit maximal que cette clé peut consommer. Un quota illimité ne signifie pas que l'usage est gratuit : la clé reste limitée par le solde du compte ou le crédit du forfait mensuel.
- **Liste de restriction des modèles** : déconseillée sauf nécessité, c'est-à-dire si vous voulez explicitement n'autoriser que quelques modèles.
- **Liste d'IP autorisées** : adaptée aux serveurs dont l'IP de sortie est fixe. À utiliser avec prudence en développement local personnel, pour éviter que les appels échouent quand votre IP change.

Symptômes fréquents d'un mauvais choix de groupe :

- Le modèle apparaît dans la liste des modèles, mais les appels avec la clé actuelle renvoient `model not found`, `model not available` ou une erreur de permission.
- Le modèle peut être appelé, mais le multiplicateur de facturation ou la stabilité ne correspond pas au niveau attendu.
- Les tokens du forfait mensuel et les tokens ordinaires sont mélangés, si bien que le crédit est imputé au mauvais compte ou que les statistiques deviennent confuses.

## 6. Vérifier la consommation réelle après usage

Après vos appels, vérifiez la consommation réelle à partir des enregistrements de **Console → Journaux d'utilisation**. En équipe, utilisez aussi l'[État de santé des groupes](/fr/group-health) pour déterminer si le problème vient d'une seule clé, d'un seul membre ou de tout un groupe.

![Exemple d'état de santé des groupes](/img/plans/statistics.png)

| Question | Champs à consulter |
| - | - |
| Quel groupe consomme le plus | Groupe, Coût, Requêtes |
| Un seul membre est-il concerné | Lignes de détail utilisateur / token |
| Le cache est-il efficace | Taux de cache, Tokens en cache, Part requêtes cache |
| Le pool de ressources est-il en cause | Taux de succès du groupe, Erreurs, Cause d'échec |
| Un long contexte ou une sortie volumineuse fait-il grimper la facture | Coût par requête réussie, Temps moyen, Tokens en cache |

## 7. Points d'attention

1. Chaque groupe correspond à un pool de ressources différent : choisissez selon votre cas d'usage.
2. Pour le forfait mensuel Codex, vous devez créer les tokens dans le groupe `codex-sub-june` ; les autres groupes ne peuvent pas utiliser le crédit du forfait.
3. Le forfait mensuel n'est pas illimité : une fois le crédit épuisé ou le forfait expiré, vous ne pouvez plus l'utiliser.
4. Pour les longues conversations Claude, tirez parti du cache de contexte. Les hits de cache réels dépendent de la configuration du client, du modèle et de l'intervalle entre les requêtes.
5. Les multiplicateurs des groupes, la disponibilité des modèles et l'état des ressources dépendent des informations en temps réel du site.

## 8. Diagnostiquer une anomalie de consommation ou de droits

En cas de consommation anormale ou de modèle indisponible, procédez dans cet ordre :

1. Vérifiez que le groupe associé à la clé actuelle inclut le modèle cible.
2. Vérifiez le solde du compte, ou que le forfait mensuel est encore valide et dispose d'un crédit restant suffisant.
3. Ouvrez **Console → Journaux d'utilisation** et filtrez par heure, modèle, token, groupe et ID de requête.
4. Comparez avec l'[État de santé des groupes](/fr/group-health) pour savoir si le problème concerne un seul token ou le pool de ressources du groupe.
5. Si vous ne parvenez toujours pas à trancher, contactez le support en fournissant le numéro de commande, le nom du token, le groupe, le nom du modèle, l'heure de la requête et l'ID de requête.
