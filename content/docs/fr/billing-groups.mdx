FishXCode est une plateforme tout-en-un d'accès aux modèles d'IA et de services de comptes, couvrant Claude, Codex, Kiro, Grok, les modèles nationaux et multimodaux. Cette page explique comment la facturation fonctionne, quels groupes existent, comment en choisir un, et comment vérifier la consommation après usage.

<Callout type="idea" title="L'information en temps réel du site prévaut">
  Les multiplicateurs des groupes, la disponibilité des modèles et les ressources évoluent avec les ressources d'amont. L'information en temps réel de la [page des tarifs](https://fishxcode.com/pricing) et de la console prévaut toujours.
</Callout>

## 1. Deux modes de facturation

| Mode | Comment c'est débité | Adapté à |
| - | - | - |
| Solde à l'usage | Prix du modèle × multiplicateur du groupe de la clé, déduit du solde du compte | Appels quotidiens, mélange de modèles, tests ponctuels |
| Forfait mensuel du pool de comptes Codex Pro | Appels avec une clé créée dans le groupe `codex-sub-june` ; la consommation réelle de tokens est déduite du quota du forfait | Programmation Codex intensive et développement d'Agents |

Pour le prix, le quota et l'usage du forfait mensuel, voir [Forfaits d'abonnement](/fr/subscription-plans).

## 3. Comment se calcule le multiplicateur

Le multiplicateur est un coefficient appliqué par-dessus le prix de base du modèle. Plus il est bas, moins la même requête sur le même modèle est débitée :

```text
Consommation réelle ≈ consommation de base du modèle × multiplicateur du groupe
```

| Consommation de base du modèle | Groupe | Débit estimé |
| - | - | - |
| 10 crédits | `codex-team` (0.12x) | 1.2 crédits |
| 10 crédits | `codex-plus` (0.2x) | 2 crédits |
| 10 crédits | `claude` (1.5x) | 15 crédits |
| 10 crédits | `claudemax` (2.6x) | 26 crédits |

La consommation de base du modèle n'est pas une valeur fixe : elle varie avec la longueur de l'entrée, celle de la sortie, les succès de cache et le prix du modèle lui-même. Les portions servies depuis le cache sont généralement moins chères.

<Callout type="warn" title="Ne jugez pas sur le seul multiplicateur">
  Le multiplicateur n'est pas le prix unique. Les prix de base, les multiplicateurs de sortie et de cache varient fortement selon les modèles ; les modèles d'image et de vidéo peuvent même être à prix fixe. Pour estimer les coûts, référez-vous aux prix en vigueur sur la page des tarifs ou dans la liste des modèles de la console.
</Callout>

## 4. Choisir le bon groupe à la création de la clé API

Lorsque vous créez une clé API dans **Console → Clés API**, le groupe de la clé définit les modèles qu'elle peut appeler, le multiplicateur de facturation et le pool de ressources d'amont : choisissez-le correctement.

![Choix du groupe à la création de la clé API](/img/start/api-v2-06-token-create.png)

À la création d'une clé API, prêtez attention à :

- **Groupe** : détermine quels modèles cette clé peut appeler et avec quel multiplicateur la consommation est facturée. Pour utiliser un forfait mensuel Codex, sélectionnez obligatoirement `codex-sub-june`.
- **Quota** : plafonne la consommation maximale de cette clé ; quota illimité ne signifie pas gratuit, la consommation reste limitée par le solde du compte ou le quota du forfait mensuel.
- **Liste de restriction de modèles** : évitez de restreindre sans nécessité, sauf si vous n'autorisez explicitement que quelques modèles.
- **Liste blanche d'IP** : pour les serveurs à IP de sortie fixe ; à manier avec prudence en développement local pour éviter des appels rompus après un changement d'IP.

Symptômes courants d'un mauvais choix de groupe :

- Le modèle apparaît dans la liste des modèles, mais les appels avec la clé actuelle échouent avec `model not found`, `model not available` ou une erreur de permissions.
- Le modèle fonctionne, mais le multiplicateur facturé ou la stabilité ne correspondent pas au niveau attendu.
- Des clés du forfait mensuel et des clés normales sont mélangées, envoyant le quota sur le mauvais compte ou brouillant les statistiques d'usage.

## 6. Vérifier la consommation réelle après usage

Après vos appels, vérifiez la consommation réelle d'après les enregistrements de **Console → Journaux d'utilisation**. En équipe, combinez en plus [État de santé des groupes](/fr/group-health) pour déterminer si le problème vient d'une clé, d'un membre ou de tout le groupe.

![Exemple d'état de santé des groupes](/img/plans/statistics.png)

| Question | Quels champs examiner |
| - | - |
| Quel groupe a le plus consommé | Groupe, consommation, nombre de requêtes |
| Un seul membre est-il anormal | Lignes de détail par utilisateur / clé |
| Le cache a-t-il fonctionné | Taux de succès du cache, tokens en cache, part des requêtes cachées |
| Est-ce un problème de pool de ressources | Taux de succès du groupe, nombre d'erreurs, motifs d'échec |
| Le coût élevé vient-il d'un long contexte ou de grandes sorties | Consommation par appel réussi, durée moyenne, tokens en cache |

## 7. Points d'attention à l'usage

1. Les groupes correspondent à des pools de ressources différents : choisissez selon le cas d'usage.
2. Le forfait mensuel Codex exige de créer la clé API avec le groupe `codex-sub-june` ; aucun autre groupe ne peut utiliser le quota de ce forfait.
3. Le forfait mensuel n'est pas illimité : une fois le quota épuisé ou le forfait arrivé à expiration, il ne peut plus être utilisé.
4. Pour les longues conversations Claude, exploitez bien le cache de contexte ; les succès réels de cache dépendent de la configuration du client, du modèle et de l'intervalle entre requêtes.
5. Les multiplicateurs des groupes, la disponibilité des modèles et les ressources sont soumis à l'information en temps réel du site.

## 8. Diagnostiquer des anomalies de consommation ou de permissions

Face à une consommation anormale ou à un modèle indisponible, diagnostiquez dans cet ordre :

1. Confirmez que le groupe lié à la clé actuelle inclut le modèle visé.
2. Confirmez le solde du compte, ou que le forfait mensuel est toujours valide avec un quota suffisant.
3. Consultez **Console → Journaux d'utilisation** en filtrant par heure, modèle, clé, groupe ou ID de requête.
4. Comparez avec [État de santé des groupes](/fr/group-health) pour déterminer si le problème vient d'une seule clé ou du pool de ressources du groupe.
5. Si cela reste indéterminé, contactez le support en fournissant le numéro de commande, le nom de la clé, le groupe, le modèle, l'heure de la requête et l'ID de requête.
