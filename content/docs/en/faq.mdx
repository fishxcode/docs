## General

### What is FishXCode?

FishXCode is a one-stop platform for AI model access and account services, covering Claude, Codex, Kiro, Grok, Chinese models, and multimodal models, usable across many tools and platforms.

### Which tools are supported?

The following tools are currently supported:

- **Claude Code** — Anthropic's official CLI
- **OpenAI Codex** — OpenAI's official coding assistant
- **RooCode** — AI coding extension for VS Code
- **Qwen Code** — Alibaba Tongyi Qianwen coding tool
- **Droid CLI** — lightweight AI coding CLI
- **OpenCode** — open-source AI coding terminal tool

### How is data privacy protected?

FishXCode acts only as an API relay and does not store your code or conversation content. All requests are forwarded directly to the corresponding model provider.

<Callout type="idea" title="Recommendation">
  For sensitive projects, read each model provider's privacy policy before use.
</Callout>

## Accounts and API Keys

### How do I register?

Visit [fishxcode.com/register](https://fishxcode.com/register?aff=9CTW), fill in a username, password, and email, then enter the verification code sent to your email to finish registration. You can also log in directly with GitHub / LinuxDO / Google third-party authorization (the first authorization creates the account automatically).

<Callout type="idea" title="Supported email domains">
  Email registration currently supports four domains: **qq.com, 126.com, 163.com, gmail.com**.
</Callout>

### How do I get an API Key?

After registering, log in to the console and go to the [API Keys page](https://fishxcode.com/keys) to create a new API Key.

### Which top-up methods are supported?

Go to **Console → Wallet** to top up. Supported:

- **Alipay**: the mainstream method, no minimum
- **Waffo Pancake**: minimum top-up $100
- **Redeem code**: enter it in the redeem area on the Wallet page

### How long is an API Key valid?

An API Key stays valid until you delete or regenerate it. Rotate keys regularly for security.

### What is my usage quota?

FishXCode provides each user a usage quota, adjusted dynamically based on platform resources. Keep an eye on the usage information in the console.

<Callout type="warn" title="Note">
  Requests are rejected once the quota is used up — plan your usage accordingly.
</Callout>

## Tool configuration

### Environment variables are set but have no effect

Check these common causes:

1. **Terminal not restarted** — after editing `.bashrc` / `.zshrc`, run `source ~/.bashrc` or open a new terminal
2. **Variable name misspelled** — names are case-sensitive; `ANTHROPIC_BASE_URL` cannot be written as `Anthropic_Base_Url`
3. **Extra quotes or spaces** — in `export KEY="value"`, do not leave extra spaces around value

<Accordions type="single">
  <Accordion title="Quick check commands">
    ```bash
    # Check whether the variables are set
    echo $ANTHROPIC_BASE_URL
    echo $ANTHROPIC_AUTH_TOKEN

    # Empty output means the variables are not in effect
    ```
  </Accordion>
</Accordions>

### Where are the configuration files?

| Tool | Configuration file path |
| - | - |
| Claude Code | Configured via environment variables |
| Codex | `~/.codex/config.toml` and `~/.codex/auth.json` |
| RooCode | VS Code settings JSON |
| Qwen Code | Configured via environment variables |

### What if I cannot connect to FishXCode?

1. Confirm `BASE_URL` is set to `https://api.fishxcode.com/` or `https://fishxcode.com/` (both work and behave identically)
2. Check that `fishxcode.com` is reachable from your network
3. On a corporate network, confirm your proxy settings are correct

## Model selection

### How do I choose the right model?

Choose by use case:

| Use case | Recommended model | Why |
| - | - | - |
| Daily coding | `claude-fable-5-2` | Balanced capability and speed |
| Fast completions | `claude-haiku-5-5` | Fast response |
| Complex architecture | `claude-fable-5-2` | Strong reasoning |

### What are the differences between models?

- **Sonnet series**: well-rounded, suits most coding tasks
- **Haiku series**: lightweight and fast, suits simple completions and formatting tasks
- For detailed capability differences, refer to each provider's official documentation

### How do I switch models?

Specify it with the `ANTHROPIC_MODEL` environment variable:

```bash
export ANTHROPIC_MODEL=claude-fable-5-2
```

## Troubleshooting

### Authentication error (Auth Error)

<Callout type="warn" title="Common causes">
  - The key was entered incorrectly (extra spaces or incomplete)
  - The key was deleted or regenerated
  - `API_KEY` and `AUTH_TOKEN` are not both set
</Callout>

Fix: go to the [API Keys page](https://fishxcode.com/keys) to check the key's status, then copy and paste it again.

### How do I view and understand error logs?

Go to [Console → Usage Logs](https://fishxcode.com/usage-logs/common) and switch the log type to **Error Logs**. You can filter by time, model, key, group, request ID, error message, and status code.

<Callout type="idea" title="Troubleshooting tips">
  - Copy the `request_id` from the API response or the log first and search it precisely in Usage Logs to find the same request
  - Search keywords in `content` via “Error message”, e.g. `Invalid token`, `Upstream request failed`
  - Aggregate issue types quickly by “Status code”, e.g. `400`, `401`, `403`, `413`, `429`, `500`, `502`, `503`, `504`
  - If the same error clusters in one group, judge from the group first whether it is a configuration, usage, or upstream availability problem
</Callout>

For full field descriptions, status code categories, and the common error table, see [Error Log Guide](/en/error-logs).

### How do I tell how widespread a group issue is?

In the [Usage Logs](https://fishxcode.com/usage-logs/common), filter by group and watch whether errors concentrate in the same group: isolated failures are usually one-off anomalies; the same error recurring across one group means that group's resource pool is affected — retry later or switch groups, and use `request_id` to locate specific requests.

For field descriptions, status code categories, and the common error table, see [Error Log Guide](/en/error-logs).

### Request timeout (Timeout)

Possible causes:

1. High network latency
2. Very long request context, so the model takes longer to process
3. High current service load

Suggestions: reduce the input context, or retry later.

### Rate limit or quota limit triggered (Rate Limit)

A `429` status code usually means requests are too frequent. It can also mean an upstream account's daily quota is exhausted, or the current model credential is cooling down.

<Callout type="idea" title="What to do">
  - Lower the request frequency and retry after a few seconds
  - Avoid calling the API in tight loops without intervals in scripts
  - Check whether another process is using the same key at the same time
  - If the log contains `Max 10/min` or `Max 5/min`, reduce concurrency and requests per minute below the threshold as prompted
  - If the log contains `daily limit exceeded`, wait for the daily quota to reset, or switch to another available model/group
  - If the log contains `cooling down`, do not retry immediately in a row; wait for the cooldown to end or switch models temporarily
</Callout>

### Model Not Available

Check that the model name is correct — see the recommended model list in [Quick Start](/en/start). Some models may not be available on FishXCode yet.
