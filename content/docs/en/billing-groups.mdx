FishXCode is a one-stop platform for AI model access and account services, covering Claude, Codex, Kiro, Grok, Chinese models, and multimodal models. This page explains how billing works, which groups are available, how to choose one, and how to check your usage afterward.

<Callout type="idea" title="Live site information takes precedence">
  Group multipliers, model availability, and resource status change as upstream resources are adjusted. The live information on the [pricing page](https://fishxcode.com/pricing) and in the console is final.
</Callout>

## 1. Two Billing Methods

| Method | How you are charged | Best for |
| - | - | - |
| Pay-as-you-go balance | The model price multiplied by the multiplier of the token's group, deducted from your account balance | Everyday calls, mixing models, quick tests |
| Codex Pro Pool Monthly Pack | Calls use a token created in the `codex-sub-june` group, and actual token usage is deducted from the pack's credit | High-frequency Codex coding and agent development |

For the monthly pack's prices, credit, and usage, see [Subscription Plans](/en/subscription-plans).

## 3. How Multipliers Work

A multiplier is a factor applied on top of the model's base price. The lower the multiplier, the less the same request to the same model costs:

```text
Actual cost ≈ base model cost × group multiplier
```

| Base model cost | Group | Estimated deduction |
| - | - | - |
| 10 credits | `codex-team` (0.15x) | 1.5 credits |
| 10 credits | `codex-plus` (0.2x) | 2 credits |
| 10 credits | `claude` (1.5x) | 15 credits |
| 10 credits | `claudemax` (2.6x) | 26 credits |

The base model cost here is not a fixed value. It varies with input length, output length, cache hits, and the model's own price. Cached portions are usually cheaper.

<Callout type="warn" title="Don't judge by the multiplier alone">
  The multiplier is not the whole price. Base prices, output multipliers, and cache multipliers vary widely between models, and image and video models may have fixed prices. When estimating costs, rely on the current prices on the pricing page or in the console's model list.
</Callout>

## 4. Choose the Right Group When Creating a Token

When you create a token in **Console -> Token Management**, the token group defines the key's available models, billing multiplier, and upstream resource pool, so make sure you choose the right one.

![Choosing a group when creating a token](/img/start/api-06-token-create.png)

Pay attention to these fields when creating a token:

- **Token Group**: Determines which models this key can call and the multiplier it is billed at. For the Codex monthly pack, you must choose `codex-sub-june`.
- **Quota**: Caps how much credit this key can consume. An unlimited quota does not mean free usage; the key is still limited by your account balance or monthly pack credit.
- **Model Restriction List**: Restricting models is not recommended unless you explicitly want to allow only a few of them.
- **IP Allowlist**: Suited to servers with a fixed egress IP. Use it with caution for personal local development, so calls don't fail after your IP changes.

Common symptoms of choosing the wrong group:

- The model appears in the model list, but calls with the current key return `model not found`, `model not available`, or a permission error.
- The model can be called, but the billing multiplier or stability is not the tier you expected.
- Monthly pack tokens and regular tokens get mixed up, so credit is charged to the wrong account or usage statistics become unclear.

## 6. Check Actual Usage After Calls

After making calls, check your actual usage against the records in **Console -> Usage Logs**. For teams, also use [Group Health Status](/en/group-health) to tell whether an issue lies with a single key, a single member, or an entire group.

![Group health status example](/img/plans/statistics.png)

| Question | Fields to check |
| - | - |
| Which group costs the most | Group, Cost, Requests |
| Whether only one member is affected | User / token detail rows |
| Whether caching is working | Cache Hit Rate, Cache Tokens, Cache Request Share |
| Whether the resource pool is the problem | Group success rate, Errors, Failure Reason |
| Whether long context or large output is driving up costs | Cost per successful request, Avg Latency, Cache Tokens |

## 7. Usage Notes

1. Different groups map to different resource pools, so choose based on your use case.
2. For the Codex monthly pack, you must create tokens in the `codex-sub-june` group. Other groups cannot use the pack's credit.
3. The monthly pack is not unlimited. Once the credit runs out or the plan expires, you can no longer use it.
4. For long Claude conversations, make good use of context caching. Actual cache hits depend on your client configuration, the model, and the interval between requests.
5. Group multipliers, model availability, and resource status are subject to the live information on the site.

## 8. Troubleshooting Billing or Permission Issues

If you notice unexpected charges or a model is unavailable, troubleshoot in this order:

1. Confirm that the group bound to the current key includes the target model.
2. Check your account balance, or confirm that the monthly pack is still valid and has enough credit left.
3. Open **Console -> Usage Logs** and filter by time, model, token, group, and request ID.
4. Compare with [Group Health Status](/en/group-health) to tell whether the issue is with a single token or with the group's resource pool.
5. If you still can't tell, contact support with the order number, token name, group, model name, request time, and request ID.
