FishXCode 是一站式 AI 模型接入与账号服务平台，覆盖 Claude、Codex、Kiro、Grok、国产模型与多模态模型。这页说明怎么计费、有哪些分组、怎么选分组，以及用完后怎么核对消耗。

<Callout type="idea" title="以站内实时信息为准">
  分组倍率、模型可用性及资源情况会随上游资源调整，最终以 [定价页](https://fishxcode.com/pricing) 和控制台的实时信息为准。
</Callout>

## 一、两种计费方式

| 方式 | 怎么扣费 | 适合 |
| - | - | - |
| 余额按量 | 按模型价格乘以 Key 所在分组的倍率，从账户余额扣减 | 日常调用、多模型混用、临时测试 |
| Codex Pro 号池月包 | 用 `codex-sub-june` 分组创建的 Key 调用，按实际 Token 消耗扣减月包额度 | 高频 Codex 编程与 Agent 开发 |

月包的价格、额度和使用方法见 [订阅套餐](/subscription-plans)。

## 三、倍率怎么算

倍率是在模型基础价格上再乘的系数。倍率越低，同一模型同一请求扣得越少：

```text
实际消耗 ≈ 模型基础消耗 × 分组倍率
```

| 模型基础消耗 | 分组 | 估算扣除 |
| - | - | - |
| 10 额度 | `codex-team`（0.12x） | 1.2 额度 |
| 10 额度 | `codex-plus`（0.2x） | 2 额度 |
| 10 额度 | `claude`（1.5x） | 15 额度 |
| 10 额度 | `claudemax`（2.6x） | 26 额度 |

这里的模型基础消耗不是固定值，会随输入长度、输出长度、缓存命中和模型本身的价格变化。命中缓存的部分通常更便宜。

<Callout type="warn" title="不要只看倍率">
  倍率不是唯一价格。不同模型的基础价格、输出倍率、缓存倍率差异很大；图片、视频模型还可能是固定价格。估算成本时，请以定价页或控制台模型列表中的当前价格为准。
</Callout>

## 四、创建 API Key 时选对分组

在 **控制台 → API 密钥** 创建 API Key 时，密钥分组就是这个 Key 的可用模型范围、扣费倍率和上游资源池，一定要选对。

![创建 API 密钥时选择分组](/img/start/api-v2-06-token-create.png)

创建 API Key 时重点看：

- **分组**：决定这个 Key 能调用哪些模型、按什么倍率扣费。用 Codex 月包时必须选 `codex-sub-june`。
- **额度设置**：限制这个 Key 最多可消耗多少额度；无限额度不代表不扣费，仍受账户余额或月包额度限制。
- **模型限制列表**：非必要不建议限制，除非你明确只允许某几个模型。
- **IP 白名单**：适合服务端固定出口；个人本地开发慎用，避免 IP 变化后无法调用。

分组选错时，常见表现：

- 模型列表里看得到模型，但当前 Key 调用时报 `model not found`、`model not available` 或权限错误。
- 能调用模型，但扣费倍率或稳定性不是预期的那一档。
- 月包 Key 和普通 Key 混用，导致额度走错账户或统计口径不清晰。

## 六、使用后核对实际消耗

调用后以 **控制台 → 使用日志** 的记录为准核对实际消耗。团队场景下，再结合 [分组健康状态](/group-health) 判断是单个 Key、单个成员还是整个分组的问题。

![分组健康状态示例](/img/plans/statistics.png)

| 问题 | 看哪个字段 |
| - | - |
| 哪个分组消耗最高 | 分组、消耗、请求数 |
| 是否只有某个成员异常 | 用户 / Key 明细行 |
| 缓存有没有生效 | 缓存命中率、缓存 Tokens、缓存请求占比 |
| 是否是资源池问题 | 分组成功率、错误数、失败原因 |
| 是否是长上下文或大输出导致费用高 | 单次成功消耗、平均耗时、缓存 Tokens |

## 七、使用注意事项

1. 不同分组对应不同资源池，请根据使用场景选择。
2. Codex 月包必须使用 `codex-sub-june` 分组创建 API Key，其他分组不适用该套餐额度。
3. 月包不是无限额度，额度耗尽或套餐到期后将无法继续使用。
4. Claude 长对话建议合理利用上下文缓存，实际缓存命中与客户端配置、模型及请求间隔有关。
5. 分组倍率、模型可用性及资源情况以站内实时信息为准。

## 八、排查消费或权限异常

遇到消费异常或模型不可用时，建议按这个顺序排查：

1. 确认当前 Key 绑定的分组是否包含目标模型。
2. 确认账户余额，或月包的有效期与剩余额度是否充足。
3. 查看 **控制台 → 使用日志**，按时间、模型、Token、分组、请求 ID 筛选。
4. 对比 [分组健康状态](/group-health)，判断是单个 Token 的问题还是分组资源池的问题。
5. 仍无法判断时，联系支持并提供订单号、Key 名称、分组、模型名、请求时间和请求 ID。
