FishXCode es una plataforma integral de acceso a modelos de IA y servicios de cuentas que cubre Claude, Codex, Kiro, Grok, modelos nacionales y multimodales. Esta página explica cómo se factura, qué grupos hay, cómo elegir uno y cómo verificar el consumo después de usarlo.

## 3. Cómo se calcula el multiplicador

El multiplicador es un factor que se aplica sobre el precio base del modelo. Cuanto menor es, menos se descuenta para el mismo modelo y la misma solicitud:

```text
Consumo real ≈ consumo base del modelo × multiplicador del grupo
```

<RatioExampleTable base={10} groups={['codex-team', 'codex-plus', 'claude', 'claudemax']} />

El consumo base del modelo no es un valor fijo: varía según la longitud de la entrada, la de la salida, los aciertos de caché y el propio precio del modelo. Las partes servidas desde la caché suelen ser más baratas.

<Callout type="warn" title="No te guíes solo por el multiplicador">
  El multiplicador no es el precio único. Los precios base, los multiplicadores de salida y de caché varían mucho entre modelos; los modelos de imagen y vídeo pueden incluso tener precio fijo. Para estimar costes, guíate por los precios actuales de la página de precios o de la lista de modelos de la consola.
</Callout>

## 4. Elige bien el grupo al crear una API Key

Al crear una API Key en **Consola → Claves API**, el grupo de la clave define los modelos que puede llamar, el multiplicador de facturación y el pool de recursos del upstream: elígelo bien.

![Elegir grupo al crear la API Key](/img/start/api-v2-06-token-create.png)

Al crear una API Key, fíjate sobre todo en:

- **Grupo**: determina qué modelos puede llamar esta clave y con qué multiplicador se factura.
- **Cuota**: limita cuánto puede consumir esta clave como máximo; cuota ilimitada no significa gratis, sigue limitada por el saldo de la cuenta.
- **Lista de restricción de modelos**: no la restrinjas salvo necesidad, salvo que permitas claramente solo unos pocos modelos.
- **Lista blanca de IP**: para servidores con IP de salida fija; úsala con cautela en desarrollo local para evitar llamadas rotas tras un cambio de IP.

Síntomas habituales de haber elegido mal el grupo:

- El modelo aparece en la lista de modelos, pero al llamarlo con la clave actual falla con `model not found`, `model not available` o un error de permisos.
- El modelo funciona, pero el multiplicador de facturación o la estabilidad no son el nivel esperado.

## 6. Verificar el consumo real tras el uso

Tras llamar, verifica el consumo real con los registros de **Consola → Registros de uso**. En equipos, usa las filas de desglose por grupo y usuario/clave de los registros para saber si el problema es de una clave, de un miembro o de todo el grupo.

| Pregunta | Qué campos mirar |
| - | - |
| Qué grupo consumió más | Grupo, consumo, número de solicitudes |
| ¿Es anormal solo un miembro? | Filas de detalle por usuario / clave |
| ¿La caché funcionó? | Tasa de aciertos de caché, tokens en caché, proporción de solicitudes cacheadas |
| ¿Es un problema del pool de recursos? | Tasa de éxito del grupo, número de errores, motivos de fallo |
| ¿El coste alto se debe a contexto largo o salidas grandes? | Consumo por llamada exitosa, duración media, tokens en caché |

## 7. Notas de uso

1. Los grupos corresponden a pools de recursos distintos: elige según el caso de uso.
2. En conversaciones largas con Claude, aprovecha bien la caché de contexto; los aciertos reales dependen de la configuración del cliente, del modelo y del intervalo entre solicitudes.
3. Los multiplicadores de los grupos, la disponibilidad de los modelos y los recursos están sujetos a la información en tiempo real del sitio.

## 8. Diagnosticar problemas de consumo o permisos

Ante un consumo anómalo o un modelo no disponible, diagnostica en este orden:

1. Confirma que el grupo vinculado a la clave actual incluye el modelo objetivo.
2. Confirma que el saldo de la cuenta es suficiente.
3. Revisa **Consola → Registros de uso**, filtrando por hora, modelo, clave, grupo o ID de solicitud.
4. Filtra por la columna de grupo en los registros para saber si es un problema de una sola clave o del pool de recursos del grupo.
5. Si sigue sin poder determinarse, contacta con soporte aportando el número de pedido, el nombre de la clave, el grupo, el modelo, la hora de la solicitud y el ID de solicitud.
