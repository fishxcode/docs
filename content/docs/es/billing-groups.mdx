FishXCode es una plataforma todo en uno de acceso a modelos de IA y servicios de cuentas que cubre Claude, Codex, Kiro, Grok, modelos chinos y modelos multimodales. Esta página explica cómo se factura, qué grupos hay, cómo elegir grupo y cómo verificar el consumo después de usarlo.

<Callout type="idea" title="Prevalece la información en tiempo real">
  Los multiplicadores de los grupos, la disponibilidad de los modelos y el estado de los recursos cambian según los ajustes de los recursos upstream. La referencia final es la información en tiempo real de la [página de precios](https://fishxcode.com/pricing) y de la consola.
</Callout>

## 1. Dos formas de facturación

| Forma | Cómo se cobra | Ideal para |
| - | - | - |
| Pago por uso con saldo | Precio del modelo por el multiplicador del grupo del token, descontado del saldo de la cuenta | Llamadas diarias, uso combinado de varios modelos y pruebas puntuales |
| Paquete mensual del pool Codex Pro | Se llama con un token creado en el grupo `codex-sub-june` y el consumo real de tokens se descuenta del crédito del paquete mensual | Programación intensiva con Codex y desarrollo de agentes |

Consulta el precio, el crédito y el uso del paquete mensual en [Planes de suscripción](/es/subscription-plans).

## 3. Cómo se calcula el multiplicador

El multiplicador es el coeficiente que se aplica sobre el precio base del modelo. Cuanto más bajo es, menos se descuenta por la misma solicitud al mismo modelo:

```text
Consumo real ≈ consumo base del modelo × multiplicador del grupo
```

| Consumo base del modelo | Grupo | Deducción estimada |
| - | - | - |
| 10 créditos | `codex-team` (0.15x) | 1.5 créditos |
| 10 créditos | `codex-plus` (0.2x) | 2 créditos |
| 10 créditos | `claude` (1.5x) | 15 créditos |
| 10 créditos | `claudemax` (2.6x) | 26 créditos |

El consumo base del modelo no es un valor fijo: varía con la longitud de la entrada y de la salida, los aciertos de caché y el precio del propio modelo. La parte que se sirve desde la caché suele ser más barata.

<Callout type="warn" title="No te fijes solo en el multiplicador">
  El multiplicador no es el único factor del precio. El precio base, el multiplicador de salida y el multiplicador de caché varían mucho entre modelos, y los modelos de imagen y vídeo pueden tener un precio fijo. Para estimar costes, toma como referencia el precio actual de la página de precios o de la lista de modelos de la consola.
</Callout>

## 4. Elige el grupo correcto al crear el token

Al crear un token en **Consola → Gestión de tokens**, el grupo del token fija los modelos disponibles de esa Key, su multiplicador de cobro y el pool de recursos upstream, así que elígelo con cuidado.

![Selección del grupo al crear un token](/img/start/api-06-token-create.png)

Al crear el token, revisa sobre todo:

- **Grupo de tokens**: determina qué modelos puede llamar esta Key y con qué multiplicador se cobra. Para usar el paquete mensual de Codex debes elegir `codex-sub-june`.
- **Límite de crédito**: limita el crédito máximo que puede consumir esta Key. Un crédito ilimitado no significa que no se cobre: el uso sigue limitado por el saldo de la cuenta o por el crédito del paquete mensual.
- **Lista de restricción de modelos**: no conviene restringir si no es necesario, salvo que quieras permitir solo determinados modelos.
- **Lista de IP permitidas**: útil para servidores con IP de salida fija. Úsala con cuidado en el desarrollo local, porque si tu IP cambia dejarás de poder hacer llamadas.

Síntomas habituales de un grupo mal elegido:

- El modelo aparece en la lista de modelos, pero al llamarlo con la Key actual se obtiene `model not found`, `model not available` o un error de permisos.
- Puedes llamar al modelo, pero el multiplicador de cobro o la estabilidad no son los que esperabas.
- Se mezclan tokens del paquete mensual con tokens normales, de modo que el crédito se descuenta de la cuenta equivocada o las estadísticas dejan de ser claras.

## 6. Verifica el consumo real tras el uso

Después de las llamadas, verifica el consumo real con los registros de **Consola → Registros de uso**, que son la referencia. En equipos, combínalos con el [Estado de salud de grupos](/es/group-health) para saber si el problema está en una sola Key, en un solo miembro o en todo el grupo.

![Ejemplo del estado de salud de grupos](/img/plans/statistics.png)

| Pregunta | Qué campos mirar |
| - | - |
| Qué grupo consume más | Grupo, Consumo, Solicitudes |
| Si la anomalía afecta solo a un miembro | Filas de detalle de usuario / token |
| Si la caché funciona | Tasa de caché, Tokens en caché, Proporción de solicitudes en caché |
| Si es un problema del pool de recursos | Tasa de éxito del grupo, Errores, Causa de fallo |
| Si el coste alto se debe a un contexto largo o a salidas grandes | Consumo por solicitud exitosa, Tiempo medio, Tokens en caché |

## 7. Notas de uso

1. Cada grupo corresponde a un pool de recursos distinto; elige según tu escenario de uso.
2. Para el paquete mensual de Codex, el token debe crearse en el grupo `codex-sub-june`; los demás grupos no pueden usar el crédito de este paquete.
3. El paquete mensual no tiene crédito ilimitado: cuando se agota el crédito o vence el paquete, ya no podrás seguir usándolo.
4. En conversaciones largas con Claude, aprovecha la caché de contexto. Los aciertos de caché reales dependen de la configuración del cliente, del modelo y del intervalo entre solicitudes.
5. Los multiplicadores de los grupos, la disponibilidad de los modelos y el estado de los recursos se rigen por la información en tiempo real del sitio.

## 8. Diagnosticar consumo anómalo o problemas de permisos

Si ves un consumo anómalo o un modelo no disponible, revisa en este orden:

1. Confirma que el grupo vinculado a la Key actual incluye el modelo que quieres usar.
2. Confirma que el saldo de la cuenta, o la validez y el crédito restante del paquete mensual, son suficientes.
3. Revisa **Consola → Registros de uso** y filtra por periodo, modelo, Token, grupo y request ID.
4. Compara con el [Estado de salud de grupos](/es/group-health) para saber si el problema es de un solo token o del pool de recursos del grupo.
5. Si aún no lo tienes claro, contacta con soporte e indica el número de pedido, el nombre del token, el grupo, el nombre del modelo, la hora de la solicitud y el request ID.
